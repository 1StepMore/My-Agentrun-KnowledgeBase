# 关于Harness工程，你可能错过的一个视角

## 核心知识点

### Harness 工程的定义与核心原理
**Harness** 借喻马具，在 AI Agent 中特指**模型以外的一切软件环境和基础设施**（如 Cloud Code、OpenCloud）。其核心原理是通过**反馈循环**（Feedback Loop）解决大语言模型输出的概率性问题：当 Agent 调用工具出错时，循环告知错误并允许修正，从而形成有效的约束机制。公式为：**AI Agent = 模型 + Harness**。  
相关概念：[[AI Agent]]、[[反馈循环]]、[[大模型概率性]]

### 当前视角的局限：过度聚焦软件工程
主流媒体和技术讨论（如 Unstoppable、OpenAI、Cursor 的博客）往往只把 Harness 用于**软件工程场景**，追求人类更少介入、Agent 运行更久、多 Agent 协作。然而这对于**一人公司**或**超级个体**而言，真正的痛点不仅是代码，更在于**多模态内容的生成质量**。这提示我们 Harness 的应用范围远不止于代码编译。  
相关概念：[[一人公司]]、[[超级个体]]、[[软件工程]]

### 多模态 Harness：控制输出质量的新视角
作者在制作视频素材生成器时发现，大模型推导的提示词不可靠且无法自我修正，原因在于缺少有效的反馈机制。关键洞察是：可以用**多模态模型作为裁判**，将用户需求分解成多维度客观问题并量化评分，再结合**搜索树算法**（记录历史轨迹）不断调整提示词，形成新的 Harness。这种**生成‑对抗**结构与 Unstoppable 提到的对抗网络完全一致，但确认者从软件工具换成了视觉模型。  
相关概念：[[多模态模型]]、[[搜索树算法]]、[[对抗网络]]

### 实例：多模态模型编排（Cartoonclaw）
论文 Cartoonclaw 展示了完整的多模态 Harness 实践——一个长视频+音频剪辑工具，由 6 个组件、4 种模态模型编排而成，体现了**生成‑对抗**的闭环。

| 组件 | 模型/工具 | 功能 |
|------|-----------|------|
| 字幕识别 | Whisper | 提取视频中的字幕文本 |
| 镜头切割 | 算法 | 检测并切割镜头 |
| 视频编辑 | Groundhog Pro | 自动完成剪辑编辑 |
| 音乐理解 | 通义千问 3 Omni | 分析和理解背景音乐 |
| 精准裁切 | MiniMax | 实现精确的视频裁切 |
| 质量审查 | 通义千问 3 VL | 从三个维度审查最终质量（对抗生成） |

相关概念：[[Cartoonclaw]]、[[通义千问]]、[[Whisper]]、[[Groundhog Pro]]、[[MiniMax]]

### MLM（多模态语言模型）的启示
英伟达对 MLM 的定义指出：世界是多模态的，数字内容不应仅限于文本。因此 Harness 工程也应当突破文本局限，扩展到对**图像、视频、音频乃至情绪**的控制。这意味着未来 Harness 的核心能力是编排多模态模型，实现复杂内容（如短剧）的自动生产，这正是**一人公司**和**超级个体**可以重点关注的方向。  
相关概念：[[MLM]]、[[多模态模型版图]]

## 总结
Harness 工程绝不仅限于解决软件工程问题，其原理（反馈循环+对抗）同样适用于**多模态内容生成**，通过让多模态模型担任裁判，可以显著提升图像、视频、音频的输出质量。对追求高效率的个体创作者而言，将 Harness 视角从代码扩展到多模态，将是实现**一人公司**和**超级个体**的关键杠杆。
