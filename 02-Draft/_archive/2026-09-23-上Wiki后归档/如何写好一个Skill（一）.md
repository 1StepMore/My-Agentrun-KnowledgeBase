# 如何写好一个 Skill（一）

> 来源：Anthropic 工程师 Frank 技术推文《How We Use Skills》| 编译：Hermes Agent

## 视频概述

Anthropic 工程师 Frank 分享了团队在 Cloud Code 中使用 Skills 的实战经验。Skills 已成为 Cloud Code 最常用的扩展机制之一，目前内部已有数百个 Skills 在日常开发中活跃使用。

本文是系列第一部分，聚焦 Skill 的整体认知与分类体系。

---

## 为什么关注 Skills

Skills 的三个核心特性：
- **灵活**：能适用于各种开发场景
- **易于创建**：上手门槛非常低
- **便于分发**：团队之间共享简单

**但灵活性也是双刃剑**——正因为什么都能做，反而让人不确定什么类型的 Skill 值得做、怎样才能写好。

---

## 常见误解

很多人以为 Skills 只是 Markdown 文件。**实际上，最有趣的 Skills 都巧妙利用了配置选项和目录结构**。

Skills 本质上是一个完整的文件夹：
```
├── skill.md          # 必需的元数据文件
├── scripts/          # 可选：脚本目录
├── references/       # 可选：参考文档目录
└── assets/           # 可选：静态资源目录
```

Skills 的关键能力：
- Agent 可主动发现并操作 Skills 中的文件
- 支持注册动态 Hooks（钩子）
- 有灵活的配置选项
- 可创造性地利用目录结构实现渐进式信息披露

**Skills 不是一段静态文本，而是一个有结构、有行为、有状态的工具包。**

---

## Skills 九大类别

> 好的 Skill 应清晰归属于某一个类别。如果横跨多个类别，往往会让人困惑。

### 前五类

#### 1. API 与 API 参考
说明如何正确使用内部或外部的库、CLI 或 SDK，通常包含参考代码片段和常见陷阱列表。

**示例**：Billing Lab——专门说明内部计费库的边界情况和各种坑。

#### 2. 产品验证
描述如何测试和验证代码是否按预期工作，通常搭配 Playwright、tmux 等外部工具。

**示例**：SideTop Flow Driver——能在无头浏览器中跑通整个注册流程。

#### 3. 数据获取与分析
连接数据和监控工具，配置数据库凭证、dashboard ID 等。

**示例**：Final Quirky——帮助回答从注册到激活再到付费，该关联哪些事件表。

#### 4. 业务流程自动化
将重复性工作流用一条命令搞定。

**示例**：Standup Post——自动聚合 Ticket、GitHub 活动和 Slack 消息，生成格式化的站会摘要。

#### 5. 代码脚手架
生成特定框架的样板代码，适合有自然语言需求、不能纯靠代码模板覆盖的场景。

---

### 后四类

#### 6. 代码质量与评审
在组织内强制执行代码质量标准。

**示例**：Adversarial Review——启动一个"新鲜眼睛"的 AI Agent 来挑刺，然后自动修复，直到问题降级为吹毛求疵的 Nit Pick。

#### 7. CI/CD 与部署
帮助获取、推送和部署代码。

**示例**：BabySitPR——监视 PR，遇到 CI 失败自动重试，碰到合并冲突自动解决，还能开启自动合并。

#### 8. 运行手册
根据一个症状（Slack 消息、报警、错误签名）自动进行多工具调查，最终生成结构化排查报告。

**价值**：对 Oncall 场景非常实用，可缩短响应时间、沉淀排查经验。

#### 9. 基础设施运维
执行日常维护和运维操作，有些涉及破坏性操作，因此特别受益于安全护栏。

---

## 九大类型覆盖范围

从开发到运维的完整生命周期：
- **开发侧**：API参考、代码脚手架
- **验证侧**：产品验证、代码质量评审
- **数据侧**：数据获取与分析
- **自动化侧**：业务流程自动化、CI/CD部署
- **运维侧**：运行手册、基础设施运维

这不是一份死板的分类标准，而是一个帮助发现盲区的**思维框架**。

---

## 三个重点类型

作者特别强调以下三类值得优先建设：

### 1. 产品验证

**价值**：对确保 Cloud 输出正确极为有用。

**建议**：甚至值得让一名工程师花一整周来专门打磨这类 Skill。

**推荐技巧**：
- 让 Claude 录像输出，这样你可以看到它到底测了什么
- 在每个步骤用程序化断点检查状态
- 在 Skill 中包含多种验证脚本

### 2. 业务流程自动化

**特点**：指令通常比较简单，但可能依赖其他 Skills 或 MCP 工具。

**关键技巧**：
- 保存执行日志
- 让模型能回溯之前的执行记录
- 保持一致性
- 支持反思和改进

### 3. 运行手册

**工作流程**：输入症状/报警 → 多工具联合调查 → 输出结构化报告

**价值**：
- 缩短 Oncall 响应时间
- 沉淀排查经验

---

## 核心要点

Skills 是有结构、有行为、有状态的工具包，不只是静态 Markdown。

优先建设三类 Skill：
1. **产品验证**——确保输出正确
2. **业务流程自动化**——提升效率
3. **运行手册**——沉淀故障处理经验
