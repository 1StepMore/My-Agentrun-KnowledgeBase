# Skill设计模式与Agent稳定输出

Agent 输出不稳定的根源，往往不在格式规范，而在 Skill 内部逻辑的组织方式。主流 Agent 工具已逐渐统一 `Skill.md` 的格式标准，真正决定输出质量的是内容设计——即知识如何加载、结构如何固定、审查如何执行、信息如何补全、流程如何管控。

通过对多种 Skill 构建方式的归纳，可提炼出五种设计模式，分别对应 Agent 最常见的五类失控点：知识加载时机不当、输出结构漂移、审查标准与流程混杂、信息不足即行动、复杂任务跳步骤。

## 模式一：Tool Wrapper——按需注入知识

**解决的问题**：知识何时加载。

**常见误区**：将某技术栈的全部规范一次性塞入 System Prompt（如框架规范、团队约定、命名规则）。大部分任务实际用不到这些信息，既浪费上下文窗口，又增加无关知识对模型的干扰。

**设计要点**：将知识放入 References，由 Skill 判断当前任务是否命中相关领域，命中才加载对应知识。Skill 充当总闸门，在合适时机将专家手册接入上下文。

**适用场景**：任务类型多样、不同任务需要不同领域知识、知识库体量超过上下文承载能力。

## 模式二：Generator——固定输出结构

**解决的问题**：输出结构不稳定。模型每次都在现场重新决定输出格式，导致同样任务产生不同结构的结果。

**设计要点**：将输出结构固定在模板中，表达方式固定在风格指南中。模板回答"要产出什么"（What to produce），风格指南回答"怎么写"（How to write）。Skill 只负责补全缺失内容并填充框架。

**适用场景**：API 文档、标准化报告、Commit Message、Changelog 生成等需要跨时间、跨人员保持结构一致的产出任务。

## 模式三：Reviewer——分离审查标准与流程

**解决的问题**：审查任务频繁返工。根因是"检查什么"与"怎么检查"被混写在一起。

**设计要点**：将两者硬拆开——Checklist 定义检查内容，Skill.md 定义检查方法。规则可随时更换而无需重写整个 Skill。输出统一为 Error、Warning、Info 三级，让使用者明确区分必须修复项、建议修改项与提醒项。

**适用场景**：代码风格审查、安全审查、合规审查等多套规则复用同一审查流程的场景。

## 模式四：Inversion——先问后答，信息齐备再开工

**解决的问题**：Agent 拿到模糊需求就急着生成，信息不足时自信地自行补全。

**设计要点**：反转流程，让 Agent 先提问、用户先回答。分三个阶段推进：

| 阶段 | 目标 | 核心动作 |
|------|------|----------|
| Discovery | 确认要解决什么问题 | 澄清问题边界 |
| Constraints | 收集限制条件 | 平台、技术栈、交付要求等 |
| Synthesis | 信息齐备后生成 | 门控指令：信息不全禁止开工 |

**适用场景**：需求模糊、信息缺口大、错误假设代价高的规划类任务。

## 模式五：Pipeline——显式工作流与门控

**解决的问题**：多步骤任务中模型容易跳步骤，尤其存在强顺序依赖时。

**设计要点**：将 Skill.md 写成明确的工作流定义——每一步做什么、何时可进入下一步，并在关键节点设置显式门控（Gate）。每一步只加载当前所需的 References 和 Templates，保持上下文干净。

**适用场景**：文档生成、复杂代码修改、发布流程、合规流程等不可跳过验证环节的任务。

## 模式选型：判断路径

选择模式前先诊断问题类型：

1. **要产出内容且从模板产出** → Generator
2. **运行时加载某套知识** → Tool Wrapper
3. **评估已有输入** → Reviewer
4. **开始前需向用户补全信息** → Inversion
5. **有严格步骤与不可跳过的门** → Pipeline

## 模式叠加

五种模式可组合使用：Generator 前可接 Inversion 澄清需求，Pipeline 结尾可接 Reviewer 做质量把关，Tool Wrapper 几乎可叠加在任何模式上补充领域知识。

**核心原则**：不要将越来越复杂的指令堆入同一个 System Prompt。先判断问题是知识问题、结构问题、审查问题、澄清问题还是流程问题，再选择对应的结构化模式。模式选对，Agent 的稳定性才能真正提升。

## 提示词引导自我认知：四句话挖掘天赋

利用 AI 进行自我认知挖掘时，提示词设计需包含四个关键要素：角色设定、方法论框架、输入材料、输出要求。

## 提示词四要素结构

| 要素 | 作用 | 示例 |
|------|------|------|
| 角色设定 | 限定 AI 的专业视角 | "扮演最顶尖的盖洛普优势教练和潜能开发专家" |
| 方法论框架 | 指定分析工具 | "运用优势识别技术和麦克利兰冰山模型" |
| 输入材料 | 提供分析依据 | 过往最有成就感的三件事、心流状态场景、当前职业阶段 |
| 输出要求 | 约束产出形式 | 可立即执行的个性化分析、日常练习方法、具体不空泛 |

## 设计要点

**角色设定要具体到可识别的专业体系**。泛化的"专家"角色不如"盖洛普优势教练"有效，因为后者自带一套成熟的分析框架和术语体系，能引导 AI 调用对应知识结构。

**方法论框架要明确**。指定分析模型（如冰山模型）可约束 AI 的思考路径，避免产出泛泛而谈的通用建议。

**输入材料要结构化**。引导用户提供"有成就感的事""心流场景""职业阶段"等具体维度的信息，而非笼统的自我描述。信息质量直接决定分析深度。

**输出要求要可执行**。明确要求"可立即执行""具体""别讲废话"，从输出端倒逼 AI 给出可落地的建议而非抽象理论。

## 通用化迁移

此提示词结构可迁移至其他自我认知场景：职业规划（角色：职业规划师 + 方法论：霍兰德职业兴趣测试）、能力评估（角色：人才测评专家 + 方法论：胜任力模型）、决策分析（角色：决策教练 + 方法论：决策矩阵）。核心逻辑一致：**限定专业视角 → 指定分析框架 → 提供结构化输入 → 约束可执行输出**。

## 关联概念

- [[Skill.md]]：Agent 技能描述文件，定义技能的行为逻辑与调用方式
- [[System Prompt]]：系统级提示词，常驻上下文，影响所有任务
- [[上下文窗口]]：模型可处理的 token 数量上限，决定知识注入的容量约束
- [[门控指令]]：流程中的显式检查点，条件不满足则禁止进入下一步
- [[麦克利兰冰山模型]]：将个人素质分为显性（知识技能）与隐性（动机特质）层面的分析框架
- [[心流状态]]：全神贯注、时间感消失的高投入状态，常作为天赋线索
- [[盖洛普优势识别]]：基于 34 项优势主题的测评体系，用于识别个人天赋模式
