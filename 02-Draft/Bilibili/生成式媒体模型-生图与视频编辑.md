# 生成式媒体模型-生图与视频编辑

## 核心分野：设计向生图与视频编辑的模型设计差异

生成式媒体模型正在分化为两条清晰的技术路线，分别解决不同场景下的核心痛点：

| 维度 | 结构化生图模型 | 参考式视频编辑模型 |
|------|---------------|-------------------|
| **核心能力** | 精确控制画面元素的布局、样式、颜色、位置 | 基于文本指令和参考素材编辑已有视频内容 |
| **输入形式** | 结构化提示词（如 JSON）定义每个元素 | 文本提示词 + 原视频 + 参考图/参考视频 |
| **典型场景** | 海报设计、电商主图、Logo 创作 | 局部编辑（换色/换背景/换装）、风格迁移、内容插入 |
| **关键架构** | 单一生成模型 + 文本编码器 + VAE | 语义规划器 + 扩散渲染器（双模块分离） |
| **主要门槛** | 提示词的结构化程度 | 提示词质量（几乎完全决定输出效果） |

两条路线的共同趋势是：**模型能力的天花板不再取决于参数量，而取决于对输入条件的理解与遵循能力**。结构化生图通过约束输入格式来提升可控性，视频编辑则通过多模态条件融合来扩展编辑能力。

## 结构化生图：JSON 提示词与元素级控制

### 结构化提示词的三大组成

设计向生图模型的核心创新在于将自然语言提示词转化为结构化数据。一个完整的结构化提示词包含三个层次：

1. **高层描述（High-Level Description）**：从整体上说明要生成什么样的图片，定义场景、主体和氛围。
2. **分隔描述（Separate Description）**：定义审美风格、光照效果、摄影类型、美学类型和调色板。
3. **构图分解（Composition Breakdown）**：包含背景描述和具体元素列表，每个元素可以是物体或文字，用坐标定义位置，并拥有独立的颜色盘。

这种结构的价值在于：**将"画什么"和"怎么画"分离**。高层描述负责整体语义，构图分解负责精确控制，分隔描述负责风格统一。

### 坐标系统与元素定位

结构化提示词使用统一的坐标系统实现精确布局：

- 以图片左上角为原点 (0,0)，右下角为 (1000,1000)
- 每个元素用四个值定义边界框：最小 Y、最小 X、最大 Y、最大 X
- 元素类型包括物体（Object）和文本（Text），文本元素需额外定义文字内容和样式描述

**关键判据**：坐标系统让模型实现了"指哪儿打哪儿"的布局控制，但需要注意——这不是图像编辑模型，本质上是重新采样生成，因此**除目标元素外的内容无法保证不变**。

### 文本渲染与拆字技巧

文本渲染是设计向生图的核心能力，但中文支持普遍弱于英文。针对中文错字问题，一个有效的技巧是**拆字说明**：

- 在文本元素的描述中追加字型结构的部件说明（如"日"+"失"= "跌"）
- 该技巧对单张图中 1-2 个错字场景效果显著，多次测试可稳定修复
- 但复杂场景下中文可靠性仍不足，建议控制汉字数量

### 透明背景与抠图工作流

结构化提示词可间接实现透明背景效果，但需注意：

- 直接要求"透明背景"只会生成棋盘格模拟效果，并非真正的 Alpha 通道
- 正确做法：生成**纯色背景**（如纯蓝、纯绿），配合"隔离主体、无阴影、无渐变、无地板线"的风格描述
- 后续用任意抠图工具一键去除纯色背景，实现产品级抠图

## 参考式视频编辑：双模块架构与条件融合

### 语义规划器 + 扩散渲染器

视频编辑模型采用双模块分离架构：

- **语义规划器（Semantic Planner）**：理解文本提示、原视频、参考图/视频，输出精确的语义规划。这是模型智能程度的关键，但常未开源。
- **扩散渲染器（Diffusion Renderer）**：专注于像素级画面生成，是实际执行采样的模块。

**核心洞察**：当语义规划器缺失时，需要外部提示词增强工具（如多模态 LLM）来补全规划能力。这意味着**提示词增强不是可选项，而是必要组件**——模型效果的上限由语义规划能力决定。

### 多条件输入的融合机制

视频编辑模型支持同时接收多种条件输入：

- **文本提示词**：描述编辑目标（增/删物体、改材质、换背景、调天气、风格迁移）
- **原视频**：提供编辑的基础内容和运动信息
- **参考图**：提供视觉细节参考（Logo、产品、人物、风格）
- **参考视频**：提供运动模式或场景参考

所有条件在 Conditioning 节点中统一汇总，生成采样所需的条件信号。关键参数包括：

- **长度**：决定最终视频总帧数，需与原视频保持一致
- **参考图最长边**：统一控制参考素材的缩放比例
- **批次数**：一次运行生成的视频数量，保持为 1 以避免显存溢出

### 视频编辑的操作类型与效果边界

基于文本指令的视频编辑可覆盖以下操作类型：

| 操作类型 | 效果稳定性 | 注意事项 |
|---------|-----------|---------|
| 换色（物体颜色） | 高 | 需锁定人物外观、姿势、背景不变 |
| 换背景 | 高 | 需指定新背景细节和光线匹配要求 |
| 风格迁移 | 高 | 需明确风格类型和渲染特征 |
| 添加/移除物体 | 中 | 边缘融合是关键，可能出现穿帮 |
| 人物老化/外貌修改 | 中 | 容易"用力过猛"，不够真实 |
| 换装 | 低 | 版型、细节难以精准控制，需多抽卡 |
| 画面分割/风格突变 | 低 | 依赖抽卡，可能出现元素串场 |

**关键判据**：换色和换背景的稳定性最高，换装和复杂特效的稳定性最低。对于专业落地场景，**无法精准控制所有细节就是不够合格**。

### 参考图引导的编辑策略

当文本难以描述视觉细节时，参考图是更可靠的引导方式：

- **Logo/产品添加**：参考图 + 文本描述"将参考图作为 Logo 添加到杯子上"，模型会自动处理弯曲贴合和光影匹配
- **风格参考**：上传风格参考图 + "把视频变成参考图的风格"，需注意区分"提取风格"与"复制视觉元素"
- **换装参考**：参考图 + 文本描述，但需提供带模特的多角度参考图，单张产品图难以传递尺寸和透视信息
- **人物替换**：参考图 + "把视频中的人物换成参考图中的人"，面部特征和发型还原度较高

**经验法则**：参考图提供"是什么"，文本提示词提供"怎么用"。两者结合时，文本应明确参考图的**使用方式**（提取风格 vs 复制元素），而非仅描述目标。

## 提示词工程：从手写到 LLM 辅助生成

### 提示词增强的必要性

视频编辑模型对提示词质量极度敏感——**最终效果几乎完全取决于提示词质量**。手动编写高质量提示词需要同时考虑：

- 明确编辑对象（"画面中心女性手中的纸质咖啡杯"）
- 锁定不变元素（"人物外貌、淡蓝色毛衣、姿势、背景街道不变"）
- 细化目标效果（"纯正鲜艳的红色，保留白色塑料盖、光影和形状"）
- 否定保护（"严格保护人物外观、衣服、姿势和背景"）

### LLM 辅助提示词生成的三级模式

使用多模态 LLM 生成提示词时，根据任务复杂度选择不同模式：

1. **简单模式**：单主体场景（普通插画、人物、风景），生成基础提示词
2. **复杂模式**：多元素对象（海报封面、多文字排版），生成完整结构化提示词
3. **可移动模式**：在复杂模式基础上避免指定元素具体位置，便于后续手动调整

**关键参数**：LLM 生成提示词时，建议提供图片比例信息；固定随机种子不一定能得到相同结果，但可在工作流中避免重复执行。

### 提示词增强的采样策略

使用 LLM 辅助时，从原视频中均匀采样 2-3 帧传递给模型，可显著节约 Token 和计算量。生成的提示词会自动包含：

- 原视频的视觉细节（人物特征、服装、环境）
- 编辑目标的精确描述
- 不变元素的保护性指令

## 模型选型与部署的量化判据

### 显存与模型格式的匹配关系

| 显存容量 | 可用格式 | 参数量级 | 备注 |
|---------|---------|---------|------|
| ≥16G | BF16 | 14B | 效果最佳，但显存占用高 |
| 12G | FP8 (E4M3FN) | 14B | 性价比最高，兼容性好 |
| 8G | GGUF Q4 | 14B | 效果有损，但可运行 |
| <8G | 轻量版 (1.3B) | 1.3B | 简单任务效果接近大模型 |

**关键判据**：
- FP8 格式中，MXFP8 在 NVIDIA 显卡上性能更优，但非 NVIDIA 环境可能反而变慢
- 量化版本（如 NF4）通常是社区从 FP8 提取的，并非原生低比特模型，效果有损
- 轻量版模型虽小，但无加速 LoRA 时采样步数多，实际速度可能慢于大模型

### 加速与优化的关键参数

- **动态 CFG**：采样前期用高 CFG（如 7）确保提示词遵循，后期降低（如 3）进行抛光。切换时机通常在前 70%-90% 的采样步骤
- **加速 LoRA**：需注意训练基础版本，可能需设置更高强度才能正常工作
- **显存优化节点**：通过调整 FFN Chunks 参数降低显存峰值，值越大显存占用越低

### 分辨率与比例的约束

- 生图模型：宽高在 256-2048 像素之间，需为 16 的倍数
- 复杂场景（尤其含中文）时，1:1 方图最稳定
- 视频模型：难以直接生成 1080P，通常需降至 480x832 左右

## Agent 集成与自动化工作流

### 结构化提示词对 Agent 的适配性

结构化提示词（JSON）天然适合 Agent 调用：

- **机器可读**：JSON 格式可直接由代码生成和解析
- **精确控制**：元素位置、颜色、样式均可编程指定
- **可复现性**：同一提示词结构可批量生成变体（换色、换位置、增删元素）

**实践案例**：通过 CLI 工具让 Agent 学会运行生图工作流，仅需一句话指令即可复刻经典海报、商标等设计。

### 工作流设计原则

- **组管理**：将可选模块（参考图、参考视频、提示词增强）封装为独立组，一键启用/禁用
- **条件切换**：确保启用增强组时使用生成提示词，禁用时回退到手动输入
- **子图封装**：将复杂流程封装为子图，降低用户认知负担

## 局限性与选型建议

### 结构化生图模型的局限

- 聚焦设计领域，人像生成质量相对较弱
- 中文文本渲染可靠性不足，复杂场景需拆字技巧
- 生成速度较慢（高画质模式约 90 秒/张）
- 非图像编辑模型，无法保证未修改区域不变

### 视频编辑模型的局限

- 语义规划器未开源，需外部 LLM 补全
- 复杂编辑（换装、特效）稳定性不足，需多抽卡
- 对提示词质量极度敏感，门槛较高
- 参考图引导时，单张参考图难以传递尺寸和透视信息

### 选型决策框架

| 需求场景 | 推荐路线 | 关键考量 |
|---------|---------|---------|
| 海报/Logo/电商图 | 结构化生图 | 提示词结构化程度决定可控性 |
| 视频局部编辑（换色/换背景） | 参考式视频编辑 | 提示词质量决定效果上限 |
| 视频风格迁移 | 参考式视频编辑 | 参考图 + 文本描述风格提取 |
| 视频内容插入 | 参考式视频编辑 | 依赖抽卡，需多轮尝试 |
| 批量生成设计变体 | 结构化生图 + Agent | JSON 提示词可编程生成 |
