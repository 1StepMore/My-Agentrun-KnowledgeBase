# CLI 编码智能体最佳实践（官方提炼）

> **L3 方法条目**。来源为 **E1 官方原文** `claude-code-best-practices`（已入库 `01-Raw/VibeCoding/anthropic-eng/`）。组织与中文表述为**我们的提炼**；**对本机 opencode / OmO 同样适用**（同为 CLI 编码智能体）。

## 一句话（全篇最重要的一条）

> **给它一个能自己跑的检查**（测试、构建、截图对比）——*"这是'你要盯着它干活'和'你可以走开'之间的差别。"*
> 没有可跑的检查，"看起来做完了"就是唯一信号，**于是你就成了那个验证循环**：每个错误都要等你发现。

## 二、四阶段工作流：探索 → 计划 → 编码 → 验证

官方明确：**把研究与计划从实现里拆出来**，否则会"很流畅地解决错的问题"。

- 进 **plan mode** 分离探索与执行（Claude Code：`Shift+Tab` 切到 `⏸ plan mode on`，或 `--permission-mode plan` 启动）
- 我们的对应：opencode 的 plan/build 模式切换；以及**长任务先出方向再动手**的规矩

## 三、环境配置清单（官方给的"该配的都配"）

| 官方项 | 作用 | 我们的等价物 |
|:---|:---|:---|
| **写有效的 `CLAUDE.md`** | 常驻的项目约定 | skill + memory + 项目页 |
| **配置权限（permissions）** | 允许/禁止的动作 | 工具审批、human-override-list |
| **接 CLI 工具** | 让它能调外部命令 | terminal 工具 |
| **接 MCP 服务器** | 扩展能力 | native-mcp |
| **设 hooks** | 在特定时点强制动作 | git pre-commit 钩子、cron |
| **写 skill** | 过程性知识 | 我们的 skill 库 |
| **自定义子代理** | 隔离脏活 | `delegate_task`、子代理批处理 |
| **装插件** | 打包分发能力 | Hermes plugins |

## 四、会话管理（官方：要"激进"）

- **早点纠偏、经常纠偏**（course-correct early and often）
- **激进管理上下文**：无关任务之间 `/clear`
- **用子代理做调查**（把"读几百个文件"的脏活关进子上下文）
- **checkpoint 回退**、**恢复会话**

## 五、规模化（官方给的升级路径）

非交互模式（脚本化）· 多会话并行 · **跨文件扇出（fan out）** · **auto mode 自主运行** · **加一个"对抗式评审"步骤**（adversarial review：让另一个 agent 专门挑错）

## 六、⭐ 六个典型失败模式（官方原文 + 修法）——最值得抄下来

| 失败模式 | 症状 | 官方修法 |
|:---|:---|:---|
| **厨房水槽会话** | 一个任务里插进无关请求，再回来，上下文塞满无关信息 | 无关任务之间 **`/clear`** |
| **反复纠错** | 越改越错，上下文被失败尝试污染 | **出错两次就 `/clear`**，把学到的写进更好的初始提示，重开 |
| **过度膨胀的 `CLAUDE.md`** | 太长 → 重要规则被噪声淹没、被忽略 | **狠心删**；**如果它不写也能做对，就删掉或改成 hook** |
| **信任-验证缺口** | 产出看起来合理但不处理边界情况 | 永远提供验证手段；**"如果你验证不了，就别发布"** |
| **无限探索** | 让它"调研一下"但没限定范围 → 读几百个文件塞满上下文 | **把调研范围框死** |
| （同上精神）| — | 把规范**沉积成机制**，不靠自觉 |

> **注意第 3 条与本库军规完全同源**：我们"skill 精简/常驻成本"的规矩，官方从"规则会被淹没"的角度给出了同一结论。
> 第 4 条则是我们"交付前必须可执行校验"的上位表述。

## 七、与本库实践的对应（E3）

- 「给它一个能跑的检查」→ 我们的**门禁 + 交付前校验脚本**（exit 0 才算过）
- 「出错两次就 /clear 重开」→ 我们的"**发现机制缺陷立刻重立检查项**"（而不是反复手工修）
- 「对抗式评审」→ 我们的**写审分离**（写正文 / 审方向）
- 「子代理做调查」→ 我们的子代理批处理（分批写盘防丢）
- 「机制而非自觉」→ 门禁三触发（写入/提交/周期）

## 八、实操清单

- [ ] 这个任务我给它**能自己跑的检查**了吗？（不能 → 我就是验证循环）
- [ ] 我**先探索/计划**了，还是一上来就让它写？
- [ ] 我的常驻规则（memory/skill）**有没有该删的**？（删掉也不出错 = 该删）
- [ ] 出错两次以上，我**重开**了吗，还是继续灌纠正？
- [ ] 调研类任务**范围框死了**吗？
- [ ] 有没有**对抗式评审**那一环？
