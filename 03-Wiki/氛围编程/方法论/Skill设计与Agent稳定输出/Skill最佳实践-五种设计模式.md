## 内容摘要

### 一、Skill 是什么

Skill 本质上是一组**结构化的持久化提示词**，与一次性提示词的核心区别在于：

- **持久化**：写一次可反复调用，无需每次重建上下文
- **可包含资源**：参考资料、脚本工具、模板文件
- **按需加载**：仅在 AI 需要时读取对应内容，避免上下文膨胀导致注意力消散

> 公式：Skill = 结构化提示词 + 参考资料 + 脚本工具 + 按需加载机制

### 二、Skill 的技术结构

Skill 由一个文件树组织（`skill.md` 必备，其余可选）：

```
skill.md          # 大脑：元数据 + 工作流程定义（必备）
scripts/          # 稳定脚本
reference/        # 参考资料、模板
assets/           # 静态资源
```

### 三、三层调用机制

1. **发现层**：AI 启动时扫描所有 Skill 的 `name` 和 `description`，仅获取可用的 Skill 列表，不读细节
2. **激活层**：用户请求与 Skill 的 `description` 匹配，命中后才调用该 Skill
3. **按需读取层**：在 `skill.md` 中通过条件分支，让 AI 按需读取文件、运行脚本或调用子 Skill

### 四、五种设计模式

| 模式 | 适用场景 |
|------|---------|
| **单任务模式** | 单一职责任务，不需要多步骤协作 |
| **顺序模式** | 多步骤串联，上一步输出作为下一步输入 |
| **并行模式** | 多个独立任务同时执行，提升并发效率 |
| **条件分支模式** | 根据输入内容或中间状态走不同分支 |
| **编排器模式** | 中心节点协调多个子 Skill，适合复杂任务 |

### 五、六步打磨法

1. **需求清晰化**：明确输入、输出、约束条件
2. **初稿生成**：基于需求写出第一版 Prompt
3. **内部测试**：用真实输入验证输出质量
4. **Prompt 迭代**：根据测试结果优化措辞、结构
5. **稳定性测试**：用多组不同输入验证结果一致性
6. **最终发布**：固化 Prompt，附上参考文档和脚本

### 六、实战案例：售前工时评估

**场景**：客户给了一段简洁需求，直接丢给 AI 调用工时评估 Skill，生成完整报价报告。

**报告内容包括**：
- 需求拆解 & 潜在需求
- 核心痛点 & 功能范围
- 用户故事（差异后）
- 功能清单 & 技术方案
- 资源配置（人员 + 投入时间）
- 影响代码分析（新增 / 修改 / 复用）
- 待确认项
- 最终报价建议

**稳定性验证**：与直接使用 DeepSeek XGB 对比（结果波动在 20~30 万），使用 Skill 后报价稳定在 **40 万上下**，显著降低项目风险。

> 这是 Skill 化设计的核心价值：**输出结果可稳定复现**，而非每次随机波动。
