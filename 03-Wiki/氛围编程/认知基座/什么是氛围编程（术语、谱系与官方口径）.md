# 什么是氛围编程（术语、谱系与官方口径）

> **认知基座第 1 篇**。读完你应该能回答：氛围编程到底是什么、和"AI 编码"什么关系、官方怎么称呼它、能力边界在哪。
> 证据标注：**E1** = 官方原文；**E3** = 社区/本库提炼。

## 一、先纠一个错位：官方**不用**"氛围编程"这个词

这是最容易被忽略的事实——**Anthropic / OpenAI 官方文档里没有 "vibe coding" 这个术语**。官方对同一件事的用词是：

| 官方用词 | 出处（E1） |
|:---|:---|
| "**agentic coding tool**"：读你的代码库、改文件、跑命令、对接你的开发工具 | [Claude Code Overview](https://code.claude.com/docs/en/overview) |
| "**agentic loop**"：读→改→跑→看结果的循环 | [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works) |
| "**context engineering**"：精确管理窗口里放什么 | [Anthropic 工程博客](https://www.anthropic.com/engineering) |

**为什么这条很重要**：拿"氛围编程"当官方口径去检索，会命中一堆自媒体二手解释；而官方权威表述是 **agentic coding / context engineering**。**术语错位 = 检索路径错误**，这是知识库必须先解决的第一件事。

（"vibe coding" 本身是 2025 年起在社区流行起来的说法，**E3/E4** 级——它描述的是"用自然语言驱动、少读代码"的**使用风格**，不是一套工程方法。）

## 二、谱系：五种形态，别混为一谈（E3，本库整理）

| 形态 | 人的角色 | 代表 | 主要风险 |
|:---|:---|:---|:---|
| ① 手工编码 | 写每一行 | 传统 IDE | 慢 |
| ② 补全式辅助 | 写、AI 补 | 早期代码补全 | 局部正确、全局错 |
| ③ 对话式生成 | 描述、复制粘贴 | 聊天式生成 | **上下文断裂**、反复返工 |
| ④ **智能体式（agentic）** | 定目标、审结果 | Claude Code / opencode / Codex | 上下文爆炸、**无人验证** |
| ⑤ 规格驱动 + 自主循环 | 写规格、定收敛判据 | SDD / Loop Engineering（E3） | 判据设计不好 → 空转烧钱 |

> ④ 才是官方文档在讲的东西；⑤ 是本库已有的方法论条目：[[SDD规范驱动开发-vs-Vibe-Coding]]、[[Loop-Engineering]]、[[goal-programming-autonomous-ai-collaboration]]。

## 三、真正的分水岭不是模型强弱，是这两件事

官方文档反复回到同一个点：**同一个模型，接不同的"外围"，结果天差地别。**

1. **上下文工程**——窗口是有限预算。官方专门做了交互式模拟讲"什么会自动加载、每次读文件花多少、规则和 hook 何时触发"（[context-window](https://code.claude.com/docs/en/context-window)），并给了 `compaction`（压缩）、`prompt caching`（缓存命中率）等具体手段。本库对应条目：[[上下文工程-用磁盘文件替代上下文状态管理]]（E3）。
2. **验证闭环**——"改完就跑、跑完就看"的确定性检查。官方层面的落点是 hooks（关键执行点插入确定性逻辑）与 sandboxed Bash（隔离前提下敢放手）；本库对应：[[告别循环修复-AI编码的防腐化工程闭环]]、[[七阶段AI开发流程-用CodingAgent交付成品的方法论]]（E3）。

合起来就是 **Harness 工程**（E3）：模型之外的一切——工具集、权限、循环控制、状态与验证。见 [[harness-工程-多模态视角]]、[[Harness工程-被忽视的视角]]。

## 四、能力边界（官方 best practices 的要点 + 我们的补充）

| 适合交给 agent | 不适合（或必须加护栏） |
|:---|:---|
| 有明确验收标准的改动（测试/构建/类型检查能判对错） | 验收标准说不清的"感觉性"需求 |
| 跨文件、重复性重构 | 强业务上下文且未落到文档里的判断（如报价、客户承诺） |
| 代码库检索、依赖审计、文档同步 | 权限敏感操作（生产库、密钥、发布） |
| 可回滚的探索（有 git 基线） | 无可回滚点的高风险变更 |

**官方给的做法**（[best-practices](https://code.claude.com/docs/en/best-practices)）：先配好环境、用 CLAUDE.md 给持久指令、并行会话扩展吞吐；**规模上去了，纪律就要上去**。

## 五、一句话结论（本库口径，E3）

> **氛围编程 = 用自然语言驱动 agent 完成编码，但要靠"上下文工程 + 验证闭环"把它的不确定性锁在可控范围内。** 它不是"不用工程"，而是把工程力气从"写代码"移到"设计约束与验收"。
