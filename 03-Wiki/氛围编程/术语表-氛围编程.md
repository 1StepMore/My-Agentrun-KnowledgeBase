# 术语表 · 氛围编程

> **三个入口之一**：词不认识先查这里，再顺「出处」进官方原文（英文一手）。
> **E1** = 官方文档；**E3** = 社区/我们自己的提炼（已标注）。官方英文原句保留在引号里，便于对原文。

## 一、核心机制（Claude Code / Anthropic 官方 E1）

| 术语 | 官方定义（英文原句 ＋ 中文释义） | 出处 |
|:---|:---|:---|
| **Agentic loop / 智能体循环** | "Understand the **agentic loop**, built-in tools, and how Claude Code interacts with your project." —— 智能体"读→改→跑→看结果"的循环，是氛围编程的引擎。 | [how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works) |
| **Context window / 上下文窗口** | "An interactive simulation of how Claude Code's **context window** fills during a session. See what loads automatically, what each file read costs, and when rules and hooks fire." —— 窗口是**有限预算**，每次读文件都付费。 | [context-window](https://code.claude.com/docs/en/context-window) |
| **Context engineering / 上下文工程** | Anthropic 官方术语：把"当前任务需要的信息"精确放进窗口，而不是把所有东西都塞进去。**这是氛围编程真正的分水岭**。 | [Anthropic 工程博客汇编](https://www.anthropic.com/engineering) · [[Anthropic-工程博客-官方一手--工程实践与最佳实践]] |
| **Compaction / 压缩** | 上下文将满时把历史对话压缩成摘要以继续工作。"why a model switch triggers a slow uncached turn, what `/compact` costs"。 | [prompt-caching](https://code.claude.com/docs/en/prompt-caching) |
| **Prompt caching / 提示缓存** | "Claude Code manages **prompt caching** automatically… how to check your cache hit rate." —— 缓存前缀命中率直接决定成本与延迟。 | 同上 |
| **Memory（CLAUDE.md / AGENTS.md）** | "Give Claude **persistent instructions** with CLAUDE.md or AGENTS.md files, and let Claude accumulate learnings automatically with **auto memory**." —— 项目级长期记忆的正确落点。 | [memory](https://code.claude.com/docs/en/memory) |
| **Subagent / 子智能体** | "Create and use specialized AI **subagents** … for task-specific workflows and improved **context management**." —— 子智能体的核心价值是**隔离上下文**，不只是分工。 | [sub-agents](https://code.claude.com/docs/en/sub-agents) |
| **Agent team / 智能体团队** | "Coordinate multiple Claude Code instances working together as a team, with **shared tasks**, **inter-agent messaging**, and centralized management." | [agent-teams](https://code.claude.com/docs/en/agent-teams) |
| **Agent Skill / 技能** | "**Agent Skills** are modular capabilities that extend Claude's functionality." / Claude Code 侧："Control which skills Claude can invoke… and author skills your sessions discover" —— 技能是**可发现的模块化能力**，比提示词更持久。 | [agent-skills/overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview) |
| **Hook / 钩子** | "Intercept and customize agent behavior at **key execution points** with hooks" —— 在关键执行点插入确定性逻辑（如提交前强制检查）。 | [hooks](https://code.claude.com/docs/en/hooks) |
| **Plugin / 插件** | "Load custom **plugins** to extend Claude Code with skills, agents, hooks, and MCP servers." | [plugins](https://code.claude.com/docs/en/plugins) |
| **MCP（Model Context Protocol）** | "Configure **MCP servers** to extend your agent with external tools. Covers transport types, tool search for large tool sets, authentication, and error handling." —— 连接外部工具的标准协议。 | [mcp](https://code.claude.com/docs/en/mcp) |
| **Sandboxed Bash tool** | "provides **filesystem and network isolation** for safer, more autonomous agent execution" —— 自主度的前提是隔离。 | [sandboxing](https://code.claude.com/docs/en/sandboxing) |
| **Agent SDK** | "Build **production AI agents** with Claude Code as a library" —— 把 CLI 能力当库用，是"从用到造"的门槛线。 | [agent-sdk/overview](https://code.claude.com/docs/en/agent-sdk/overview) |
| **Tool use / 工具调用** | "Connect Claude to external tools and APIs. See **where tools execute**, when Claude calls them, and which tool fits your task." | [tool-use/overview](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) |
| **Context editing** | "Automatically manage conversation context as it grows with **context editing**." | [context-editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) |
| **权限模式（permission mode）** | "A **permission mode** sets which actions Claude can take in a session without asking you first." —— 决定"哪些动作不用问你"，是自主度的总开关。 | [permission-modes](https://code.claude.com/docs/en/permission-modes) |
| **Manual 模式（`default`）** | 官方表：`default` = "**Reads only**" —— 除读取外几乎每个动作都要问。适合敏感工作/逐条审阅。 | 同上 |
| **Plan mode** | 官方一节标题即定义：**"Analyze before you edit"** —— 只读 + 探索，等你批准计划再动手。`Shift+Tab` 循环切换。 | 同上 |
| **Auto mode + classifier** | "a second model, the **classifier**, reviews actions instead of you" —— 由第二个模型在**服务端**替你审阅动作；还有"分类器默认拦什么""何时回退"等规则。 | 同上 |
| **`acceptEdits`** | 官方表："Reads, file edits, and common filesystem commands" —— 自动接受文件编辑，适合"边看边改"。 | 同上 |
| **`dontAsk` / `bypassPermissions`** | 前者只放行**预先批准过的工具**；后者**跳过全部检查**（高风险，官方单列一节）。 | 同上 |
| **Context rot / 上下文腐化** | 官方：needle-in-haystack 类研究显示**窗口内 token 越多，模型准确召回能力越差**，且**所有模型都有**此现象。 | [Anthropic 工程博客](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) |
| **Attention budget / 注意力预算** | 官方：LLM 的注意力如人的工作记忆，**每个新 token 都在消耗有限预算**，边际收益递减 → "塞得多 ≠ 记得住"。 | 同上 |
| **Progressive disclosure / 渐进披露** | 官方机制：agent 启动时**预载所有 skill 的 name+description**（第一层），正文按需再读。解释了我们"description 必须自带触发条件"的根因。 | [agent-skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) |
| **Guardrail / 护栏** | OpenAI 官方：对输入/输出/工具/流程做校验的机制，命中时由 **tripwire 立即中止**（不是记日志继续跑）。 | [Agents SDK guardrails](https://github.com/openai/openai-agents-python/blob/main/docs/guardrails.md) |
| **Tripwire** | 官方：护栏命中后**中止执行并抛错**的触发线——"护栏要有咬合"。 | 同上 |
| **HITL（Human-in-the-loop / 人在环）** | 官方：工具自己声明"需要批准"，运行结果以**中断**形式暴露待批项；`RunState` 可序列化，暂停后恢复；审批面是**运行级**的（跨 handoff/嵌套）。 | [Agents SDK HITL](https://github.com/openai/openai-agents-python/blob/main/docs/human_in_the_loop.md) |

## 二、方法论术语（E3，我们的提炼／社区）

| 术语 | 说明 | 证据 |
|:---|:---|:---|
| **Harness / Harness 工程** | 模型之外的一切：工具集、权限、循环控制、状态与验证。同一模型接不同 harness，产出天差地别。见 [[harness-工程-多模态视角]]、[[Harness工程-被忽视的视角]]。 | E3 |
| **Loop Engineering / 循环工程** | 把"循环"当成可设计对象（触发条件、收敛判据、成本上限）。见 [[Loop-Engineering]]、[[Loop-Engineering实操指南]]。 | E3 |
| **SDD（规格驱动开发）** | 先写规格再让 agent 实现，与"氛围式随手写"相对。见 [[SDD规范驱动开发-vs-Vibe-Coding]]。 | E3 |
| **Vibe coding / 氛围编程** | 社区术语：以自然语言驱动、少看代码的编码方式。**注意**：它不等于"不要工程纪律"——官方 best practices 强调验证与评审。见 [[_MOC-氛围编程]] §5 学习路径。 | E3 |
| **Ralph loop / Ralph Wiggum 方法** | 社区收敛出的做法：用 hooks/脚本把 agent 按在**持续迭代循环**里（Anthropic 官方长任务文中提及）。我们这个 `/goal` 机制与此同源。 | E3/E4 |
| **七阶段 AI 开发流程** | 用 coding agent 交付成品的方法论（本库整理）。见 [[七阶段AI开发流程-用CodingAgent交付成品的方法论]]。 | E3 |

## 三、工具专有词（用户实际在用的）

| 术语 | 说明 | 出处 |
|:---|:---|:---|
| **opencode** | 终端 AI 编码 agent（本库主力工具）。术语见 [[opencode-官方文档汇编-中文--01-快速开始与核心概念]]。 | E1 |
| **Oh-My-OpenAgent（OmO）** | opencode 的增强插件/工作流封装（用户在用的 "OMO" 即此，**此前误记为 Oh-My-OpenCode**）。官方：code-yeongyu/oh-my-openagent。见 [[Oh-My-OpenAgent（OmO）使用指南]]。 | E2 |
| **`permission`（opencode）** | 官方：决定某操作**自动运行 / 提示审批 / 被阻止**，取值 `"allow"` / `"ask"` / `"deny"`；⚠️ 规则**最后匹配者优先**（通配 `*` 必须写最前）。`v1.1.1` 起旧 `tools` 布尔配置并入此项。 | opencode 官方中文文档 |
| **`external_directory`（opencode）** | 官方：允许工具访问**启动目录之外**的路径；`~`/`$HOME` 展开**只影响写法**，不会把目录纳入工作区——出工作目录必须显式允许。 | 同上 |
| **primary / subagent（opencode）** | 官方两种 agent 模式：`primary`（build 全工具 / plan 受限）+ `subagent`（general / explore 只读 / scout 只读查外部文档）。 | 同上 |
| **`rules`（opencode）** | 官方：项目级持久指令，思路等同 Claude Code 的 `CLAUDE.md`。 | 同上 |
| **`~/.omo/omo.jsonc`（OmO）** | 官方：**统一一份**配置管所有 omo harness；用户层 `~/.omo/omo.jsonc` + 项目层 `.omo/omo.jsonc`（逐级向上）。旧文件名只有迁移引擎读。 | OmO 官方文档 |
| **`ultrawork` / `ulw`（OmO）** | 官方：OmO 的旗舰工作流入口；⚠️ 并行 agent 会显著提高 token 消耗，适合中等以上任务。 | 同上 |
| **Instruction Files ≠ Enforcement** | 官方原话：`AGENTS.md` 是**指令上下文**，**不是确定性权限边界**；确定性强制来自 OMO 配置 / 内置限制 / OpenCode 权限门 / 守卫 hook。 | 同上 |
