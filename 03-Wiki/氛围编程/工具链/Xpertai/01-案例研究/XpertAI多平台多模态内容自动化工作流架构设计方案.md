一、总体架构
本系统采用分层架构设计，自上而下分为五个层次：触发与调度层、选题池与评分服务层、多智能
体与工作流编排层、多模态能力层和外部集成层。各层之间通过 XpertAI 的统一状态通道（会话变
量）进行数据流转，实现松耦合、高内聚的系统结构。以下逐一描述各层的职责与组成。
1.1 系统分层概述
系统整体分为五层架构。最上层为触发与调度层，负责按照预设时间规则自动启动各项工作流；第
二层为选题池与评分服务层，作为数据中枢管理选题的全生命周期；第三层为多智能体与工作流编
排层，是系统的核心执行引擎；第四层为多模态能力层，封装内容生成能力；最底层为外部集成层
，对接各发布平台。各层通过 XpertAI 的会话变量机制实现数据共享与流转。
1.2 触发与调度层
触发与调度层是系统的入口，负责按照预设的时间规则自动启动各项工作流。基于 XpertAI
的"定时任务工具集"实现，支持 Cron 表达式配置，可创建一次性或周期性任务，并指定执行智能
体与指令。本系统配置四个核心定时任务：
 选题生成任务（每日
7:00）：触发"热点监控与选题生成专家"，抓取当日热点并生成候选选题，写入选题池。
 内容创作任务（每日 8:00）：触发"Supervisor
Agent"，从选题池中选取高分选题，协调多专家生成多平台内容。
 发布任务（每日
10:00）：触发"发布与集成执行专家"，将合规检查通过的内容发布到各平台。
 效果回采任务（每日 12:00）：延迟 24
小时回采已发布内容的阅读量、互动率等效果数据，用于评分权重反馈优化。
所有定时任务均配置失败通知，通过企业微信或邮件将异常信息推送给运维人员。
1.3 选题池与评分服务层
选题池与评分服务层是系统的数据中枢，负责选题数据的持久化存储、评分计算、排序和末位淘汰
。选题池以本地 JSON 文件为主存储，通过工作流的"代码执行"节点实现读写操作。评分服务通过
加权求和模型对每个选题进行多维度评分，不同题材类型（引流/服务介绍）使用不同的权重配置。
评分结果用于选题排序和选取，确保每次创作都优先选择最具价值的选题。
选题池的容量管理采用"末位淘汰"策略：当池中选题数量超过上限（默认 50
条）时，自动淘汰综合评分最低的选题。被淘汰的选题记录淘汰时间，进入 7
天"冷却期"，冷却期内不会被重新生成。这种机制确保选题池始终保持新鲜度和高质量。
1.4 多智能体与工作流编排层

多智能体与工作流编排层是系统的核心引擎，负责协调多个数字专家完成从选题到发布的全流程。
本层采用"Supervisor + 子智能体"的层级型多智能体架构，Supervisor Agent
作为总调度器，负责任务分解、子智能体选择和结果汇总。子智能体各司其职，在 Supervisor
的指挥下并行或串行执行各自的任务。
在工作流编排上，本系统采用"Agent + Workflow 混合编排"模式。对于需要高度创造性、灵活应
对不确定输入的环节（如热点分析、选题生成、内容创作），采用 Agent 节点，赋予其较大的自主
决策空间；对于流程固定、需要精确控制的环节（如合规检查、评分计算、数据持久化、API
调用），采用 Workflow 节点，确保执行的可预测性和可追溯性。
在 XpertAI 项目中，建议采用"规划模式"进行多智能体协作。规划模式下，Supervisor 先分析任务
、制定执行计划，然后按计划调度子智能体执行。这种模式特别适合多平台内容生成场景：Superv
isor 将一个选题拆分为多个平台的内容生成任务，分发给对应的平台策略专家并行执行，最后汇总
所有平台的内容制品进入合规检查和发布流程。
1.5 多模态能力层
多模态能力层封装了系统的内容生成能力，包括文字生成、图片生成和视频生成。底层 LLM 使用
Minimax（在 XpertAI 中配置为默认模型），负责文字内容的生成与分析。多模态生成能力通过
XpertAI 的 Skills/插件机制封装为可复用的 Skill，供工作流节点按需调用。
 Minimax LLM：作为默认大语言模型，负责选题分析、文字内容生成、合规文本分析、摘要
生成等文字类任务。
 Minimax 图片生成 Skill：封装 Minimax 的图片生成
API，支持根据文本描述生成封面图、配图等。注册为自定义
Skill，支持指定尺寸、风格等参数。
 Minimax 视频生成 Skill：封装 Minimax 的视频生成
API，支持根据分镜脚本生成短视频。支持指定时长、分辨率、风格等参数。
 知识库检索工具：基于 XpertAI 的知识库能力，支持对企业品牌信息、服务介绍、历史案例等
文档的上传、分块、嵌入和语义检索。
 Web 搜索工具：用于热点监控、事实核查和信息补充，支持搜索微博热搜、百度热榜、知乎
热榜等公开信息源。
1.6 外部集成层
外部集成层负责与各内容发布平台对接，实现内容的发布或半自动发布。微信公众号通过官方 API
实现全自动发布（草稿创建、素材上传、群发）；知乎、小红书、抖音、B
站采用半自动方案（生成草稿/操作清单，人工确认后记录日志）。所有外部 API 调用通过
XpertAI 的 HTTP 请求节点或代码执行节点实现，封装为可复用的自定义工具/Skill。
此外，外部集成层还包括素材存储（本地文件系统，按日期和平台组织目录结构）和通知渠道（企
业微信 Webhook、邮件 SMTP，用于关键状态通知和错误告警）。素材存储路径建议为

二、数据与状态设计
本节定义系统中的核心数据实体、字段结构以及持久化方案。数据设计遵循"可查询、可追溯、可回
滚"的原则，确保选题池、内容制品和发布日志的完整生命周期管理。所有数据通过工作流的会话变
量与外部存储（本地 JSON 文件）联动，实现状态在多次工作流执行之间的持久化。
2.1 核心数据实体
系统包含三个核心数据实体：Topic（选题）、Content（内容制品）和
PublishLog（发布日志）。一个 Topic 可以对应多个
Content（同一选题在不同平台发布），一个 Content 对应一条 PublishLog。

2.2 持久化方案
考虑到单机本地部署的资源限制，采用"本地 JSON 文件 +
工作流会话变量"的混合持久化方案。JSON 文件作为主存储，工作流会话变量作为运行时缓存。
 选题池存储：使用单个 JSON 文件（topics_pool.json），路径为
/data/xpertai-content/topics_pool.json。每次操作后通过代码执行节点写回文件。
 内容制品存储：每个内容制品保存为独立 JSON 文件（content_{id}.json），存放在
/data/xpertai-content/contents/ 目录下，同时维护索引文件 contents_index.json。
 发布日志存储：使用追加写入的 JSONL
文件（publish_log.jsonl），每行一条记录，适合日志类数据的高效追加和查询。
 素材文件存储：图片和视频素材存储在 /data/xpertai-content/assets/
目录下，按日期和平台分子目录组织。
 会话变量联动：工作流启动时通过代码执行节点读取 JSON 文件到会话变量；执行过程中通过
会话变量在节点间传递数据；结束时通过代码执行节点将变更写回 JSON 文件。
为防止数据丢失，建议配置每日自动备份任务，将 /data/xpertai-content/
目录压缩打包后存储到备份位置。JSON
文件采用"写入前备份"策略：每次写入前先将当前文件复制为 .bak
后缀的备份文件，确保写入失败也能回滚到上一个一致状态。

三、工作流设计（主流程 + 子流程）
本节详细描述系统的工作流设计，包括主工作流拓扑和各子流程。工作流采用 XpertAI 的 Agent +
Workflow 混合编排模式，在同一流程中组合高自主性的 Agent 节点与高可控的 Workflow
节点。主工作流覆盖从选题生成到内容发布的完整链路。
3.1 主工作流拓扑
主工作流采用"定时触发 + 管道式处理"的拓扑结构。每日早间（建议 7:00）通过定时任务触发器启
动，依次执行选题生成、评分排序、内容创作、合规检查、发布等环节。对于需要多平台并行处理
的环节，采用迭代/列表操作器节点实现并行分发。下图展示了主工作流的完整拓扑：

4.2.1 Supervisor Agent（总调度器）
Supervisor Agent 是整个系统的指挥中心，负责接收定时任务触发信号，将整体任务分解为子任务
，选择合适的子智能体执行，并汇总各子智能体的执行结果。Supervisor 采用"规划模式"工作：先
分析当前任务状态（选题池是否充足、是否有待发布内容等），制定执行计划，然后按计划依次或
并行调度子智能体。
Supervisor 的核心决策逻辑包括：判断是否需要生成新选题（选题池中"待处理"选题数量低于阈值
时触发选题生成）、决定当日创作哪些选题（基于评分排序和题材比例）、协调多平台内容生成的
执行顺序（在单机环境下采用伪并行策略）、以及处理各环节的异常情况（降级、重试、人工队列
）。所需工具：定时任务工具集、逻辑分支、列表操作器、代码执行。
4.2.2 热点监控与选题生成专家
该专家负责每日的热点信息采集和选题创意生成。工作流程为：首先通过 Web 搜索工具抓取当日
主要热榜（微博热搜、百度热榜、知乎热榜、抖音热点等），提取热点关键词和话题摘要；然后通
过知识库检索获取企业服务标签和品牌信息；最后通过 Minimax LLM
将热点信息与企业服务进行创意关联，生成候选选题。
选题生成时需要同时考虑两种题材类型：引流题材（以热点为切入点，吸引眼球，结尾自然带出企
业介绍）和服务介绍题材（从热点出发，解释企业服务能为目标客群带来什么）。每个候选选题需
要标注类型、预估热度、时效性评分、关联服务标签等信息。生成后通过代码执行节点进行去重处

五、选题池与评分机制
选题池是系统的核心数据结构，用于管理候选选题的全生命周期。每日自动生成若干候选选题，经

作时从池中选取评分最高的选题，确保内容质量。当选题池容量超过上限时，自动淘汰评分最低的
选题，保持池中选题的新鲜度和高质量。

5.3 末位淘汰策略
选题池采用"容量上限 + 末位淘汰"的管理策略，具体规则如下：
 容量上限：选题池中最多保留 50
条选题（可配置）。当新增选题导致池中数量超过上限时，触发末位淘汰。
 淘汰规则：按 total_score
升序排列，淘汰评分最低的选题。若评分相同，优先淘汰创建时间较早的选题（FIFO
原则）。
 冷却期机制：被淘汰的选题进入 7 天冷却期。冷却期内，该选题的关键词和主题不会被重新生
成（通过去重逻辑过滤）。冷却期结束后，选题从记录中彻底移除，可以重新生成类似选题。
 保护机制：状态为"处理中"或"已发布"的选题不参与淘汰。只有"待处理"状态的选题才会被淘汰
。
 淘汰周期：每次新增选题后检查是否需要淘汰（即"实时淘汰"），而非定期淘汰。这确保选题
池始终保持在容量上限以内。

7.1 必检项清单
合规检查涵盖四个维度，每个维度包含多个必检项：
7.1.1 法律与监管合规
 广告法合规：检查内容是否包含"最""第一""国家级""独家"等绝对化用语；是否包含虚假承诺或

 未成年人保护：检查内容是否涉及未成年人信息的不当披露；是否包含可能对未成年人产生不

 敏感领域审查：检查内容是否涉及金融投资建议（需合规声明）、医疗健康建议（需免责声明
）、法律咨询（需资质声明）等敏感领域。
 政治与社会争议：检查内容是否涉及敏感政治话题、社会争议事件；是否可能引发舆论风险。
 个人信息保护：检查内容是否包含未经授权的个人隐私信息。
7.1.2 版权与素材来源
 图片版权：检查所有图片素材是否为 AI 生成或已获授权；是否包含水印或版权标识。
 文字原创性：检查内容是否与已发布内容高度相似（通过知识库中的历史内容比对）；引用部

 数据引用：检查引用的数据是否有权威来源；数据是否准确无误。

 品牌调性：检查内容风格是否与企业品牌调性一致（通过知识库中的品牌指南比对）。
 服务承诺：检查内容中涉及的服务承诺是否与企业实际服务范围一致；是否包含超范围的承诺
。
 联系方式：检查内容中的联系方式、网址等信息是否正确。
7.1.4 事实与数据准确性
 事实核查：检查内容中的事实陈述是否准确；通过 Web 搜索工具进行交叉验证。
 数据准确性：检查引用的数据、统计、排名等是否来自权威来源且准确无误。
 时效性验证：检查引用的热点信息是否仍然有效（避免引用已过时的热点）。
