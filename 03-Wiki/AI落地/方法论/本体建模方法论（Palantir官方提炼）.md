# 本体建模方法论（Palantir 官方提炼）

> **L3 方法条目**。基于 **E1 官方原文**（`ontology/why-ontology`、`ontology/models`，中文页为官方机翻）；中文表述与组织为**我们的提炼**，引用论断请回英文原版。

## 一句话

> **本体的价值不在"把数据存得更整齐"，而在把**决策**变成可复用资产**——它是组织的"共享真实数据源"，读数据、写回决策、让模型与业务流程直连。

## 一、为什么要建（官方五条价值论证）

| # | 价值 | 官方说法 |
|:--|:---|:---|
| 1 | **规模化连接** | 单一真实数据源，用户"能发现并理解组织里有什么数据"，还能**在全局上下文里看自己的局部决策**。⚠️ 官方明确对比：**从数据湖直接操作会导致"数据集/仪表盘/应用数量不断膨胀"的不可控复杂度**，新项目重复造轮子 |
| 2 | **可解释性** | 把"表、合并"这类数字概念**抽象掉**，让非技术决策者用**日常术语**与数据交互；并提供跨职能的**共享语言**（不用冗长对账确认为什么看到的不一样）|
| 3 | **规模经济** | 把力气集中到**一个可复用数据资产**上，所有分析与应用开发共享它；新数据的集成只需做一次，**应用与应用场景可以建立在既有本体之上** |
| 4 | **决策捕获** | 本体把**组织做出的决策捕获为数据**（配置数据输出与操作类型，定义用户如何编辑/丰富数据）。捕获的决策让组织**从中学习**；一个用户捕获的洞察可为另一个用户的决策做贡献——**数据资产价值复利增长** |
| 5 | **支持运营 AI/ML** | 模型（及特征）可直接绑定到本体的对象/流程上，**无需适配器或粘合代码**即可在平台内或外部服务；决策与操作**写回本体**，形成**反馈闭环** → 使模型监控、评估、重训、MLOps 成为可能 |

**两个官方案例（可直接用于对客说明）**

- **能源公司**：不同角色（石油工程师 / 井完整性工程师 / 井管理人员）共享同一个"井"Object 的**健康与性能视图**——不再为同一口井造孤立视图，短期运维与长期资产投资**基于同一份信息**。
- **制造业客户**：飞机传感器监控数据因规模/复杂度/格式深奥，**此前运营与数据科学家都取不到**；建模进本体后，**设计师可自行搜索部件、查看异常读数**，无需理解表或合并。原本数据准备要几天到几周（只能用于特殊项目），现在工程师、质量控制、设计师**都能直接用**。

## 二、建什么（元素清单）

语义元素（世界是什么）：**Object 类型 / 属性 / 共享属性 / 链接类型 / 接口**
动力元素（怎么改变世界）：**操作类型 / 函数 / 角色（权限）**
→ 定义与出处见 [[术语表-AI落地]]；完整官方原文见 [[palantir-本体论-Ontology官方体系]]

## 三、怎么建（两条官方端到端流程）

**A. 数据 → 本体（核心路径）**
1. 识别业务实体与事件 → 定义 **Object 类型**（模式定义）
2. 定义**属性**（含跨类型复用的**共享属性**）
3. 定义**链接类型**（把孤立的实体连成图）
4. 定义**操作类型**（用户能做什么编辑，以及提交时的**副作用**）
5. 需要计算/逻辑时用**函数**（可接受 Object 与对象集作为输入）
6. 用**接口**表达具有共同形状的类型（多态）
7. 用**角色**控制 Ontology 级 / 资源级权限

**B. 模型 → 本体（AI/ML 运营化的官方 5 步）**
1. 创建**建模目标**（把 ML 项目的组织理由写清楚）
2. 模型**开发或从外部集成**
3. **评估**（定量 + 定性）后**部署**为可交互查询
4. 用点击式界面把模型的**输入输出映射到本体概念**
5. 映射完成后模型**无缝可用于应用开发**（结果直接呈现给最终用户；亦可在系统级场景中模拟全组织变更）

## 四、什么算"建成了"（官方隐含判据，我们的归纳）

- [ ] **共享语言**：非技术角色能用日常术语自助取数？（"可解释性"是否成立）
- [ ] **决策在回流**：用户的编辑/决策是否成为数据资产的一部分？（"决策捕获"）
- [ ] **可复用**：新场景是否复用了既有对象/链接，而不是新建一套？（"规模经济"）
- [ ] **模型已直连**：模型结果是否绑定在本体概念上，无需粘合代码？（"支持运营 AI/ML"）
- [ ] **有反馈闭环**：操作与流程数据是否写回本体，支撑监控/重训/MLOps？

## 五、用法（E3，我们的实践）

- **对客表达**：官方五条价值 + 两个案例是现成的**说服材料**（尤其"数据湖 → 本体"的复杂度对比）。
- **报价/交付**：端到端流程可直接作为**工作量分解依据**（数据侧 7 步 / 模型侧 5 步）。
