## 字幕（Whisper AI 转写，MiniMax 后处理）

上期我们装好了 Hermes Agent，看到了它的自学能力。但它跑在终端，你得坐在电脑前才能用。今天我们把它接入到飞书，接完之后无论你在电脑上还是手机上发条消息，AI 就开始干活，定时任务的结果也会直接推送到你的聊天窗口，走在路上、躺在床上都能用。

大家好，我是小木头，这是 Hermes Agent 系列的第二期。

Hermes 内置了一个叫 Gateway 的进程，专门负责接入聊天平台。目前 Hermes 支持了 14 个以上的平台，主流的应用像 Telegram、飞书、Discord、钉钉、企业微信、WhatsApp 等等，都能够非常轻松地集成。它们全部跑在同一个网关。

我首先来分享一下，在已经集成好的飞书中是如何与 Hermes Agent 进行交互的。现在我集成的这个 Hermes AI 应用，或者说聊天机器人，就是飞书中我已经完成了集成的一个小小的企业自建应用。

在这里我已经完成了一些对话，大家可以来看一下。如果看过上期视频的朋友应该知道，在上一期视频我让 Hermes Agent 帮助我创建了一个定时任务。我让这个定时任务每天帮我刷新 Hacker News 上那些与 AI 相关的内容和话题。

在这里我就通过聊天的方式，让他帮我列出当前这个定时任务，我可以对这个任务做一番调整。举个简单的例子，我让他把这个任务的执行调整到每天早上 6 点，我希望他把这个任务的执行时间改到 UTC 的早上 6 点，看看他的执行情况。

首先，Hermes 会给到我一个响应。在这个消息上标记 OK，表示他已经收到消息开始工作。在定时任务上他会做 update，也就是更新。看起来这个任务已经被更新到了早上 6 点，他做的工作依然是 Daily Hacker News AI RSS Fetch，这个就是在上一期视频分享中我们已经创建好的一个任务。

另一方面，我们可以看看在这个任务中所用到的技能。看起来他告诉我并没有使用到任何技能。在上一期视频的最后，它根据之前的执行经验总结并创建了一个新的技能，我来看看它是否能够找到这个技能。

我告诉它，在上一次似乎它创建了一个技能来获取到在 Hacker News 中 AI 相关的一些内容。看起来它用到了 Session Search 这个工具，尝试去回忆是否有这方面的一些内容或技能。接下来他用到了一系列的工具，比如 skills list、build、view，这些工具的使用帮助他最终定位到了这个新的技能。看起来这个技能确实是创建了，只是在刚才的这个定时任务中还没有使用它。

对话的分享就先到这里。在飞书中我们可以做更多的操作，实际上我们就像使用一个智能体一样与其交流就好了，Hermes Agent 会作为它的后端，智能化为我们提供服务。

我们今天的话题是如何在 Hermes Agent 集成飞书，那现在我们就来演示一下。

首先是创建飞书企业自建应用，来到飞书开放平台，在开发者后台这里创建一个新的企业自建应用。我将其命名为 Hermes Junior，选一个图表颜色，添加一个应用描述，创建。

在这个应用中，我们首先添加机器人的能力。接下来来到权限管理这里，我们需要为它开通一些权限。在 Hermes Agent 官方文档这里，似乎并没有关于如何配置飞书应用的权限这部分的内容。不过不要紧，咱们来友好地参考一下 OpenAI 所提供的这部分配置。

在 OpenAI 的文档这里有这么一段配置，关于开通了一些权限。我们可以复制它，回到飞书开放平台，在权限管理这里批量导入导出权限，点击它，在导入这里删掉已经存在的部分，粘贴我们刚才复制的，点击下一步，确认新增权限，点击申请开通，点击确认。

在这一步会授权关联应用的身份权限，其中就包含了获取用户的 UUID。在开通权限前或权限后，大家务必留意一下这些权限是自己预期或期望开放给这个应用的。

在完成这一步操作后，来到事件与回调。在事件配置这里，点击订阅方式，选择使用长连接接收事件，点击保存。点击回调配置，点击订阅方式，同样使用长连接接收回调，保存。在这种配置下，它就会利用 WebSocket 来与 Hermes Agent 进行交互，这也是最方便的一种配置方式。

现在回到事件配置这里，参考 OpenAI 文档，在下方复制这个事件，im message receive v1，回到飞书开放平台，在事件配置这里添加新的事件，粘贴进来。我们只需要添加这一个接收消息的事件就可以了。

好了，配置完成。现在我们要做的就是创建个版本，在上方点击创建版本，给它一个应用版本号，添加一份更新说明，保存，确认发布。这样我们就完成了应用的创建。

接下来需要回到凭证与基础信息这里，获取它的 App ID 以及 App Secret。咱们先将页面保留在这里，回到自己的终端。

现在可以参考 Hermes Agent 官方文档，在飞书集成部分，来到第三步配置 Hermes。我们复制这段命令，Hermes Gateway Setup，在终端输入这段命令，运行，在这里做飞书的配置。大家可以看到飞书这部分，我已经完成了配置，不过我可以依然选择它来做重新配置，那我就再配置一遍，我们一起来过一下这个步骤。

输入 1 表示再配置，在这里输入 App ID 以及 App Secret。我们回到飞书开放平台，复制应用凭证中的 App ID，在终端粘贴它。接下来粘贴 App Secret，同样复制这个 Secret，回到终端粘贴。大家在这里粘贴后是不会看到 Secret 明文的字符串的，确保我们正确地做到粘贴的操作，然后回车。

再选择 Domain，如果大家使用的是国内的飞书版本，就默认的飞书没有问题。如果大家用的是国际版，务必在这里输入 LARK。我们不输入，那默认就是飞书国内版本。

连接方式，刚才我们介绍的使用的是长连接，对应的就是 WebSocket，不输入也行，默认就是 WebSocket。

最后是配置什么用户可以发送消息，也就是一个白名单。我在这里已经配置了我目前的飞书账号的 ID，那么同样呢，我将它粘贴进来。这就是如何设置一个白名单，粘贴我的 ID，回车。

接下来配置一个聊天 ID，用于接收定时任务的消息或者通知。在这里即使我们不设置，后续的飞书应用的集成或者对话中按需要也会提出我们授权。我们现在先完成在 Hermes 这里的配置。接下来要求重启网关来应用刚才的配置，我们就将网关重启一下。操作完成，现在我们就完成了所有需要的配置。

来到飞书，在开发者助手这里打开我们创建的这个应用 Hermes Junior，发送消息看看吧，看看效果如何。

看到了吗？Hermes Junior 给我们打了个 OK 的标记，表示他收到消息正在回复。很快的给了我们这么一个配对的命令，这个命令跟 OpenAI 的配对非常的相似。我们将这个命令复制一下，回到自己的终端，输入这个命令执行。完成配对，接下来就可以正常地使用飞书应用了。

我们回到飞书，再给他打个招呼。Hermes Junior 同样标记了个 OK，表示他收到消息正在准备给我回话。我们收到了来自 Hermes Agent 发送的消息。这样的端到端就已经接通好了。

这就是咱们今天所分享的如何在 Hermes Agent 集成飞书。在视频开始的时候所做的演示中，我们与 Hermes 这个 AI 应用的聊天，可以看到记忆是共享的。在上一期视频中所做的操作是在 Hermes TUI 进行的聊天，那么在 Hermes 这个 AI 应用中，同样的能引用到过去的聊天的记忆。它通过会话的搜索，也能够发现在过去我们做了什么。

感兴趣的朋友可以来尝试一下，毕竟这是一种更加便捷的与 Hermes Agent 进行对话的体验。

简单介绍一些注意事项：

首先当然是安全第一，大家务必在使用中设置白名单。刚才在飞书集成中我们也演示了如何设置用户账号或者用户 ID，从而只有这个唯一的 ID 或允许的 ID 才能够与这个机器人进行对话。

另一方面，Token 或者 Secret 一定要保密，不要泄露。一旦泄露了，就赶紧去对应的平台重新生成。

接完聊天平台之后，Hermes 就真正的变成了一个随时在线的 AI 助手。你不需要开终端，手机上发条消息就能让他干活。现在他已经接上了飞书，或许每天早上你打开手机，你想要的摘要信息报告就已经推送到你的聊天窗口了。
