好，我們開始動手前，先要弄清楚到底要做什麼。這聽起來簡單，但這是我的第一步。很多人跳過這步，後面結果就很差。你要研究有沒有類似產品，市面上已經有哪些方案，然後再決定技術棧，還要確定用哪些工具，要有足夠清晰的整體方案，而不是一上來就讓AI帶著你亂做一個產品。

那這期影片裡，我想做的是一個AI Shorts工具。它有點像Opus Clip——如果你聽過的話——就是上傳一條長YouTube影片，讓AI自動生成一堆短影片。短影片會帶字幕，並自動把16:9橫屏重構成9:16豎屏，也就是把橫屏影片變成豎屏短影片，同時還要能挑出精彩片段，加上標題、字幕之類的東西。這就是我的想法，你做什麼都行，但先從想法開始。

有了想法之後，接下來就要做點研究，先搞清楚這個項目應該用什麼技術棧，然後確定這個技術棧裡要用哪些工具，最後還要再把開發環境配好，這樣後面用這些工具才會更順手。馬上你就能看到我錄之前做了點研究，接下來會講我是怎麼做的。我先做了幻燈片，其實這個幻燈片是我用Claude Code生成的。我基本上就是把想法寫進Prompt，告訴他我想做什麼，幫我調研一下，看看應該用哪些工具，再確定一個適合這個項目的技術棧，然後帶著幾個問題和他來回聊了幾輪，慢慢整理出工具、流程和應用的大概樣子。這就是第一階段。我不在這裡展開太久，先快速過一遍這次會用的工具，看我是怎麼規劃的。

我在調研時發現，這個應用裡相對簡單的部分，其實是判斷哪些內容適合剪成短片段，也就是看一遍影片的轉錄文本，然後判斷這一段內容可以單獨剪出來。真正難的地方在於，怎麼把這些選中的片段變成實際的影片檔案，對吧？有了時間軸，怎麼剪、怎麼轉格式、加字幕、做串流播放並保持速度，還有下載、上傳以及各種和影片處理相關的事情，這些都要考慮。本地做當然可以，但做成Web應用會複雜很多。所以這期影片裡，我判斷自己會需要三個主要工具：第一個是Whisper，這裡用的是Groq提供的版本，它主要負責音頻轉文字，這樣我們就可以把音頻傳進去，先把音頻文件裡的內容轉成文字；後面我們還會用到Claude負責挑片段並生成Caption和標題；還會用ImageKit，它長期贊助本頻道，這期也很適合用它，我們可以把選中的精彩瞬間直接變成影片。具體後面講。想跟著做的話，ImageKit可以免費用。

到這一步，我基本已經想清楚這個應用需要哪些核心組件，也決定把它做成Web應用，所以我會用Next.js。這也是我和Claude討論之後定下來的，我們覺得這套技術棧更適合這個項目。接下來就是怎麼把它做出來，這就要用到接下來的AI工具了。我馬上現場給你看怎麼配置。這裡我會用Cursor配合Claude的模型搭建專案。模型有很多選擇，但從零開始時，我通常更偏向最新的Claude，也就是你看到時最新的Claude版本，通常表現更好。如果要大重構、反覆修改或總出同類錯，我會切到GPT-5；如果只是改UI，我會用更快的模型，比如Composer 2.5。所以接下來，我先把Cursor配置起來，我會給它加一些Agent Skills和相關工具，這樣後面調用這個項目需要的服務會更順手。

思路明確了就開始，先裝好並打開Cursor，我來展示環境配置。現在打開Cursor，先新建一個專案，你可以看到我把側邊的智能體視窗也打開了。這裡我已經選好了要用的模型，因為Fabro 5現在還不能用，所以先用這個。然後我進入Added，在這裡把這個模式打開，Thinking Mode保留上下文視窗開到100萬，強度選Medium，對大多數功能來說比較均衡，也可以選High或XHigh，但更慢，也會花錢。它不是完全免費的，但這是我平時用的配置。Agent Modes也能改，不過現在先保持一個智能體視窗。我個人更喜歡這個視圖，因為它能讓我直接看到所有文件，我不喜歡那個智能體界面，那個默認基本就是和智能體聊天，我不太喜歡那種方式，因為對我來說能直接看到他在寫什麼代碼會更踏實。我通常就在右邊聊天視窗操作。我覺得Cursor比Claude Code更好用，包括Codex也一樣，雖然底層可能用的是同一批模型，但Cursor團隊做的這套Coding Harness更順手，實際用起來也更穩，這是我的個人體驗，所以我一直用它。不過我也開著Claude Code，有時候也會用它的聊天視窗，比如單獨聊點想法，或者做一些資料研究，又或者我希望內容能保存下來之後在不同設備上也方便查，我就會直接在Claude裡處理。像演示文稿、影片研究和功能規劃，我都會在那邊整理，這些我會放在單獨視窗裡做，不放在Cursor裡。寫代碼時我才用Cursor。

所以接下來，在Cursor裡我第一步要做的就是先把我們要開發的東西規劃清楚。我通常會直接在Cursor裡口述，把想法講出來，同時把已經確定的技術選擇和產品決定都告訴他。我電腦上有個工具叫Whisper Flow，馬上你就能看到他怎麼工作，它可以讓我直接對著麥克風說話，然後把我說的內容實時轉成文字，這樣整個過程會快很多。我也推薦你用，這裡先演示一下，它基本就是我和AI協作時使用的口述工具。它在Cursor裡是原生支持的，比如可以直接Tag文件之類的。我會直接說：我想做一個AI Shorts工具，思路是上傳一個較大的16:9橫屏影片，然後讓它自動拆成多個更短的影片片段。也就是說，我給它一條長影片，它幫我生成一組適合發布的短影片。這個過程我希望主要靠分析音頻轉錄文本來完成，並且用Next.js做成一個Web應用。然後我打算用這些工具：首先影片轉錄這部分用Groq的Whisper，我會提供Groq API Key；再用Claude Sonnet挑出精彩片段，然後再給這些Shorts生成標題和Captions；最後我想用ImageKit處理所有圖片和影片相關的任務，比如把人物臉部重新構圖，還要添加Captions，並生成可線上播放的影片格式；另外影片上傳下載這些流程也希望它一起處理掉。你能不能先幫我給這個應用寫一份高層級規劃，也就是架構文檔？這樣專案就有完整上下文。開始前有問題可以先問我。

好，我知道這個Prompt確實挺長，但我真正想做的是先給這個專案建立一份初始上下文，這樣我們就能在應用裡生成一些Markdown文件，之後不管開多少次聊天，都可以反覆引用這些信息。之後開多個Agent或並行任務時，他們都能理解應用和一座決定內容已確定。現在直接運行Whisper Flow，可免費用，我也和他們長期合作，鏈接在描述區。它還會顯示一些統計數據。很明顯，說話比打字快多了。我們等它跑完，影片裡我會跳過等待，很長的Prompt等它跑完我再回來，給你們看它到底生成了什麼。

其實現在已經到這一步了，它開始問我幾個問題，所以我接下來會一個一個回答。我建議開始就在Prompt裡讓模型先問問題，現在Cursor也有內置功能，可以直接回答這些問題。我先打完這些問題，然後繼續配置環境。好，這裡的問題我已經打完了。趁他繼續處理，我順便給你們看一下為什麼我知道這些工具能做到什麼。錄之前我先確定要用哪些工具，也建議你們這樣做。這次我用ImageKit，他也贊助了本頻道。我本來就知道他，並確認他支援圖片和影片自動優化，他還有Resize、Crop、Transform這些功能，他還能做人臉對齊，自動把畫面焦點跟著臉移動。所以只要我知道這個工具有哪些功能，我就更清楚該讓AI模型去做什麼，因為我讀過文檔，也理解這個工具大概能提供哪些能力。

Groq這邊也是一樣，我看了一下，發現他們有Whisper Large v3 Turbo，這是速度很快的語音辨識模型，我們可以用API Key調用，分析文本並返回結果。所以有了這些基礎信息，知道這些工具大概能做什麼，我就能更準確地告訴AI模型該怎麼幹活。

接下來等這個規劃提示詞跑完，拿到初始上下文之後，我們就開始添加各種MCP Server，這些會加到Cursor裡，我會按正在用的工具來配置。現在很多工具比如Firecrawl或者各種新框架，通常都會提供Agent Skills或者某種MCP Server，幫助模型理解這個工具該怎麼用。以ImageKit為例，這個鏈接我會放在描述區，頁面叫Build with AI，裡面有Agent Skills、MCP Servers和純文本文檔。這樣我就不用自己讀完文檔再複製貼上，也不用直接丟個網站URL給模型，我可以直接安裝這些Skills，讓智能體知道怎麼用這個工具。所以我現在來到Cursor Setup這一塊，把這裡的命令直接複製下來，然後到我的Terminal裡執行。我們打開Terminal，把它跑一下，它應該會自動安裝這些Skills並加到Cursor裡面。你可以看到跑完之后，這裡已經有Agent Skills了，ImageKit提供的一堆Skills也已經內置進來，Cursor現在就能用了。

另外我們還要加上MCP Server。這裡說可以把MCP Servers加到Cursor的mcp.json，不過我連手動改文件都不想做，直接告訴Cursor幫我添加這些MCP Servers。好，它應該就能自動幫我加進去，然後給MCP Server做認證，讓他登入並管理ImageKit帳號。如果你想跟著做，也需要一個ImageKit帳號，它可以免費用，當然它也有Pro版本可以升級，升級後帶寬更高、存儲更多、上傳限制也更寬之類的。創建帳號後就能拿到配置信息，從描述區鏈接進入Developer Options就能看到Endpoint URL和Private Key，基本上這就是連接並驗證ImageKit的方式。我剛重載了視窗，因為它提示MCP Server已添加，要讓它生效只需要打開MCP Settings。我現在在Cursor裡用命令面板，快捷鍵Command+Shift+P（Windows是Ctrl+Shift+P），輸入MCP，打開MCP Settings。現在MCP Server已經添加了，Puppeteer MCP Server也可以一起加。接下來我在ImageKit API這裡點Connect，然後貼上我的ImageKit Private Key。這些都是在搭環境，目的是讓後面開發更高效。我先複製這個Key，現在已經連上ImageKit並能管理帳號，這些都透過MCP Server操作。MCP Server部分還能搜索文檔。到這裡Cursor配好了，MCP Server和需要的Skills都有了。如果用其他工具，也用同樣方法把集成加進來。

接著我想快速看一下這裡已有的文檔，確認內容有沒有問題，也看看它是不是把我們現有的工具大致梳理清楚。好，從架構和路線圖來看還挺不錯的，當然後面我們隨時還可以先改。我先把這些改動保留下來，不好意思，我得點到這個位置，然後保留它剛才生成的改動。然後我會讓它在這裡配置Git，這樣所有東西都能保存下來，之後需要的話也方便回滾。所以我很推薦大家加上GitHub MCP Server，這樣它就可以直接幫你創建倉庫。我會告訴模型，新建一個Repository並開始配置專案，以後只要有比較大的改動就都自動提交一次Commit，這樣後面需要的話也方便回滾。我還會把它寫成這個項目的專門規則，每次重大修改之後都要Commit，而且盡量自動完成。我現在其實是在加另一個功能，也就是給Cursor配規則。Cursor可以生成Rules，等下應該會自動生成這些Rules，後面會一直帶進提示詞上下文，大概就是這麼個作用。你可以看到它已經給我們建了一個叫Rules的文件夾，還生成了一個規則文件，我希望寫代碼時自動做這件事。現在他好像又在移動這個文件或者做一些整理，不過重點是他會把這條規則建好，不用每次提醒他Commit，他會自動做好。現在規則已經創建好了，GitHub Repository也建好了，我的GitHub帳號裡也能看到。

接下來就開始真正搭建項目。我先整理需要用到的API Keys，比如ImageKit的Public Key、Private Key、URL這些，還有Groq的API Key。我發現它寫成了Grok，我要用的是Groq，所以這裡得改一下。我直接跟模型說明就行。這種把名字搞錯的情況其實很常見，我不是要用Grok，我要用的是Groq，用它來做轉錄。好，我們把這個告訴他，希望他接下來會按這個來改。他已經改好了。我把API Key填進.env.local，就能開始構建應用。

那現在我就可以直接跟他說開始執行任務，按剛才的計畫把功能搭起來。Cursor現在有Multi Agent也叫Multi Task，可以把它打開。我平時其實不太用，因為它有時候會跑得有點失控，最後會讓項目不好維護。不過這次我們配置得還不錯，所以這次應該能跑起來。我們試試讓他同時拉起多個Agent，盡快搭出項目。

第一個Prompt跑完了，整體已經搭出來了。現在已經有這些項目了，不知道為什麼這個地方失敗了，後面當然要調試。不過影片上傳這部分是成功的，剛才從這裡上傳了影片，我們去Media Library看一下，這裡已經成功加載了影片，證明上傳功能正常。這是從長影片裡剪的一小段，文件335MB，沒問題。這裡提醒一下，如果你用的是ImageKit免費版，單個文件最大只能上傳100MB，這點要注意。我現在用的是Pro版，上線是2GB，還有其他功能。描述欄裡能看到說明各套餐差異，想升級可參考。

接著我會告訴他這裡失敗了，我上傳了一個影片，然後得到這個結果。失敗時我就這麼做：如果有報錯，我就把錯誤信息直接複製進去，再補一句「上傳完成後進入轉錄階段時出現了這個錯誤，ImageKit轉錄沒跑，幫我調試」。我會多給一點上下文，而不是只丟報錯，讓他知道上傳這是正常的，希望他順著調試。但跑著跑著，我發現方向好像不對，看起來他可能是想把整個影片文件都拿去處理，他把完整影片發給Groq做轉錄，這不是我想要的。我會跟他說：先確認一下，我們應該先把影片轉換一下，把它變成只有音頻的文件，不要影片畫面，只把音頻文件發給Groq做轉錄，這樣文件會小很多。而且ImageKit是可以處理這種轉換的，ImageKit能從影片裡擷取音頻，也支援很多Transformation。模型能查到，因為已連上MCP Server。但我知道這些，是因為我提前看過不少文檔，也研究過ImageKit在這個場景裡能做什麼，比如它能重構畫面、也能調整影片尺寸，它還支援自適應碼率串流媒體，所以我們可以實施預覽，還能擷取出音頻並透過URL做轉換。你看它的工作方式其實很簡單，不需要特殊操作，把查詢參數加到影片URL後面就行，它就會自動而且快速地幫你完成這些轉換，這也是我們會用它的原因。

總之我們先等它跑完，希望沒問題。看起來能用，再測一次。我再上傳一個影片，看看轉錄是不是正常，也看看現在這個應用整體跑到什麼狀態了。我展示這些是因為，用AI開發就是會出錯，所以我會認真看模型在說什麼，弄清楚它在做什麼，也會看工具調用，這樣能很快判斷它是否跑偏。它是不是要跑偏了？然後我就可以馬上打斷它，或者像這次一樣，我讓它修一下，它就回到自己的體係裡自己調整，希望這次能跑通。我剛重測了一遍，看起來可以了，效果挺不錯。下面有轉錄文本，也有剪出來的片段。片段還沒加載出來，估計從ImageKit拉取要一點時間，但至少它已經選出了區間。好，你看，現在開始顯示了。不過片段這裡還有個Bug，它給了完整4分鐘，不是轉換後的片段，所以我再給它發一個Prompt告訴它現在發生了什麼。不過至少在推進。

接下來我準備這樣做：我先截一張圖，這對模型很有幫助，因為模型能直接看到UI上的問題。但我還是會把具體問題標出來，再把圖加進去，然後告訴他：現在轉錄已經能用了，但我們其實還沒有真正生成任何轉換後的片段，現在只是原影片重複顯示五次，需要真正用ImageKit生成片段，生成五個不同的影片，而且要確保這些任務是並行處理的，同時還要加上Captions，並且做Face Reframing，還要轉成9:16。我再補點細節讓它更清楚。運行看看結果。來回改了一會兒，幾個小錯誤已經修掉了，這些先不展開。片段已生成，看一下你會發現它大概會跟著我的臉移動，不過這個片段選的不是特別好，所以還可以繼續調整System Prompt，一輪輪迭代。但現在能下載和重新渲染，也能顯示縮略圖，縮略圖也是ImageKit生成的。現在還缺Captions，ImageKit可以把Captions直接燒入進影片，短影片當然需要這個。所以我回到模型讓它加上這個功能。現在都能跑了，只差燒入Captions，每個片段添加Captions。好，過了幾分鐘，我們回來了。現在可以看到底部已經有Captions了，不過位置還不夠高，所以這裡還需要再傳一個Prompt。先把它靜音，讓滑鼠先移開一會兒，應該能看到下面有Captions，就在實際片段的底部。不過當影片播放器出現時，播放器會擋住字幕，可以讓它往上移。但先這樣，至少這部分完成了。

到這裡這個項目基本就做完了。最後確實有很多來回和混亂，但這就是AI編碼的現實。總結一下我們做了什麼：影片一開始我們先做了什麼深入研究，弄清楚要構建什麼並做關鍵決策，比如Tech Stack、工具、不同的API以及我們要用的東西；然後創建了一些上下文，然後在Cursor裡建立上下文，說明目標和要做的東西；接著做決策，並讓模型先做一輪提問，類似訪談的過程；之後，我們開始設置Cursor，安裝Agent Skills、MCP Servers以及不同的規則或圖靈，讓它知道項目大部分內容該怎麼做。所以現在所有代碼其實都已經在GitHub上了，因為我們有GitHub MCP Server，也添加了ImageKit Agent Skills。有了MCP Server，就不用去文檔裡複製貼上或者去讀一堆資料，其實可以讓模型自己做，因為我們說過我們要用這些工具，並把他們提供給模型。之後就是反覆提示，先讓它跑起來，有Bug就來回調試修掉。現在項目跑起來了，這個完成版應用當然還可以繼續微調，但總體來說已經大概用了5到10個Prompt，不算我剪掉的部分。因為一開始Tooling就已經配好了，如果我們沒有添加這些工具、沒有MCP Server，也沒花時間規劃，當然會多花很多時間，甚至可能根本做不完這個項目。

好了各位就到這裡，這期影片就結束了。希望你覺得有用，如果覺得有用記得點讚、訂閱這個頻道，我們下期再見。
