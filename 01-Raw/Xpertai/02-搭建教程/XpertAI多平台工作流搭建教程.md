# XpertAI 多平台工作流搭建教程

> 此文档为原始素材，请勿直接修改。编译后的知识请移步 `02-Draft/` 目录。

## 原文内容

XpertAI 多平台工作流搭建教程本文旨在为 AI 工作流工程师与内容自动化运营人员提供一份清晰、专业的 step-by-step 指南，指导您从零开始搭建基于 XpertAI 的多平台内容自动化工作流。本教程严格遵循分阶段实施路线图，以逻辑严谨、语言简洁的技术文档风格，详细阐述环境准备、核心流程构建、平台扩展及精细化运营的完整过程。所有操作均具备实际可操作性，并融入了关键参数说明与失败应对策略，确保您能成功部署并持续优化该系统。一、引言：XpertAI 多平台工作流概述本教程的核心目标是指导用户搭建一个完整的多平台内容自动化流程，实现从热点选题到合规发布的端到端闭环。该工作流利用 XpertAI 平台的 Agent + Workflow 混合编排能力，将内容生产的关键环节——自动选题、跨平台生成、合规发布与效果反馈——进行标准化和自动化。核心能力说明：* 自动选题：通过“热点监控与选题生成专家”实时抓取微博、百度等热榜信息，结合企业服务标签，自动生成高潜力候选选题。* 跨平台生成：由“Supervisor Agent”统一调度，针对不同平台（微信公众号、知乎、小红书、抖音/B站）调用对应的“策略专家”，生成符合平台调性的图文或视频脚本。* 合规发布：在发布前，通过“合规与风控审查专家”执行法律、版权、品牌一致性与事实准确性四维度检查，确保内容安全。* 效果反馈：通过延迟触发机制回采各平台数据，形成“创作-发布-反馈-优化”的数据闭环，驱动评分权重动态调整。本教程适用于具备基础技术背景的 AI 工作流工程师与内容自动化运营人员。读者需熟悉 XpertAI 平台的基本操作，并对 API 集成、JSON 数据格式有基本了解。二、准备工作在开始搭建工作流之前，请务必完成以下环境与资源的预检与配置，这是确保后续步骤顺利进行的基础。2.1 环境与权限确认请按顺序执行以下检查项：1. 验证 XpertAI 版本：登录您的 XpertAI 控制台，进入“系统设置” &gt; “关于”页面，确认已部署的版本号为v1.0或更高。若版本过低，请先升级至指定版本。2. 获取管理员权限：确保当前登录账户拥有项目创建、API 密钥管理及插件安装的管理员权限。如无此权限，请联系系统管理员进行授权。3. 安装必要插件：在 XpertAI 的“插件市场”中，搜索并安装以下四个核心插件：○ Minimax LLM○ Web Search○ HTTP Request○ Code Execution安装完成后，在“我的插件”列表中确认其状态为“已启用”。2.2 参考资料准备为保证工作流设计的一致性，请参照以下步骤准备参考资料：1. 下载设计蓝本：访问公司内部知识库，下载《XpertAI_multi_platform_workflow_design.pdf》文件，并将其保存至本地作为设计参考。2. 创建本地目录结构：在您的服务器或本地机器上，执行以下命令，创建用于存储工作流数据的标准目录：bash mkdir -p /data/xpertai-content/{contents,assets,drafts}3. 初始化知识库：登录 XpertAI 项目空间，进入“知识库”模块，上传以下三类文档：○ brand_info.txt：包含企业品牌介绍、核心价值主张。○ service_tags.json：定义所有对外提供的服务及其关联标签。○ historical_cases.zip：打包历史成功案例文档，用于案例适配度分析。三、阶段一：MVP 构建（聚焦微信公众号图文内容）本阶段的目标是快速搭建一个最小可行产品（MVP），仅聚焦于微信公众号图文内容的自动化生产，以验证核心流程的可行性。3.1 创建核心数字专家在 XpertAI 项目中，依次创建以下四个核心数字专家（Agent/Workflow）：1. 注册 Supervisor Agent：○ 在“智能体”页面点击“新建”。○ 命名智能体为Supervisor Agent。○ 在“高级设置”中，勾选“启用规划模式”，使其能够自主制定任务执行计划。2. 添加“热点监控与选题生成专家”：○ 新建一个名为热点监控与选题生成专家的 Agent。○ 在“工具”选项卡中，绑定Web Search和Minimax LLM插件。○ 在“提示词”中明确其职责：“你是一个热点分析师，负责抓取当日热搜，并结合企业服务标签生成5-10个候选选题。”3. 添加“选题评分与排序专家”：○ 新建一个名为选题评分与排序专家的 Workflow 节点。○ 此节点将使用代码执行插件运行评分算法。4. 添加“微信公众号策略专家”：○ 新建一个名为微信公众号策略专家的 Agent。○ 绑定Minimax LLM插件，并为其加载微信公众号的内容模板。3.2 搭建主工作流骨架创建一个新的主工作流，命名为 Main_Content_Workflow，并按以下顺序连接节点：1. 添加“定时触发器”节点：○ 配置 Cron 表达式为0 7 * * *，表示每天早上7:00自动触发。○ 设置超时时间为300秒。2. 连接“热点监控”Agent 节点：○ 将“定时触发器”的输出连接到热点监控与选题生成专家。○ 在节点配置中，将输入字段date设置为{{trigger_time}}，输出字段映射为candidate_topics。3. 添加“选题评分”Workflow 节点：○ 连接上一步的输出。○ 在代码执行节点中，嵌入评分权重 JSON：json { "traffic": {"heat_score": 0.35, "timeliness_score": 0.25, "platform_fit": 0.15, "history_effect": 0.10}, "service": {"service_tag_cover": 0.35, "case_fit": 0.20, "audience_match": 0.15} }○ 失败应对：若评分计算失败，使用默认权重重新计算；若仍失败，将所有候选选题标记为“待人工评分”。4. 添加“内容生成”分支：○ 添加一个“逻辑分支”节点，根据topic_type字段路由。○ 对于traffic类型，连接微信公众号策略专家。○ 在专家节点中，调用 Minimax LLM，输入为选题描述和品牌信息，生成 Markdown 格式的长文内容。5. 添加“合规检查”节点：○ 使用合规与风控审查专家Workflow 节点。○ 执行法律合规、版权风险、品牌一致性、事实准确性四项检查。○ 突出安全降级机制：若合规检查节点本身执行失败，强制将所有待检查内容标记为pending_manual，进入人工审核队列，遵循“宁可误拦、不可漏放”原则。6. 添加“半自动发布”节点：○ 添加一个“代码执行”节点，编写脚本将合规通过的草稿内容写入本地目录。○ 输出路径为/data/xpertai-content/drafts/wechat/content_{id}.md。3.3 数据持久化配置为确保数据不丢失，需正确配置数据持久化：1. 配置 topics_pool.json 文件路径：○ 在“选题评分”节点的代码执行脚本中，将读写路径硬编码为/data/xpertai-content/topics_pool.json。○ 确保 XpertAI 进程对此文件有读写权限。2. 设置 content_{id}.json 索引机制：○ 每次生成新的内容制品后，创建一个独立的 JSON 文件，文件名为content_&lt;UUID&gt;.json，存放于/data/xpertai-content/contents/目录下。3. 实现“写入前备份”策略：○ 在任何对 JSON 文件的写入操作前，首先执行cp /path/to/file.json /path/to/file.json.bak命令，生成备份文件。3.4 MVP 测试验证完成上述配置后，进行全流程测试：1. 手动触发一次：在工作流控制面板中，点击“立即运行”按钮，手动触发一次流程。2. 检查关键产出：○ 查看/data/xpertai-content/topics_pool.json是否已更新，且新增了候选选题。○ 检查/data/xpertai-content/contents/目录下是否生成了新的content_*.json文件。○ 确认/data/xpertai-content/drafts/wechat/目录下已导出.md草稿文件。3. 记录指标：记录本次流程的平均耗时（应低于15分钟）与成功率（应达到90%以上）。若任一环节失败，请根据日志排查原因。四、阶段二：扩展平台与题材在 MVP 验证成功的基础上，本阶段将工作流扩展至更多平台，并支持服务介绍类题材。4.1 新增平台策略专家1. 添加“知乎策略专家”：○ 新建一个名为知乎策略专家的 Agent。○ 绑定Minimax LLM插件，并为其配置深度图文模板，要求包含引用支撑和数据图表。2. 添加“小红书策略专家”：○ 新建一个名为小红书策略专家的 Agent。○ 除绑定Minimax LLM外，还需集成Minimax Image Generation Skill用于生成封面图。○ 提示词中强调“要点化文案”和“清单化表达”。3. 在 Supervisor 中添加逻辑分支：○ 修改Supervisor Agent的规划逻辑。○ 当收到一个选题时，解析其target_platforms字段（例如["wechat", "zhihu", "xiaohongshu"]）。○ 动态地将生成任务路由给对应的平台策略专家并行处理。4.2 支持服务介绍题材1. 修改评分权重配置文件：○ 更新scoring_weights.json文件，增加service_tag_cover和case_fit的权重，使其在service类型选题中的总和占比超过60%。2. 在“内容生成”节点中加入题材判断逻辑：○ 在Supervisor的规划阶段，当识别到topic_type为service时，自动将该选题的生成任务标记为高优先级。3. 对服务类选题启用人工审核队列机制：○ 在“合规检查”节点之后，添加一个“条件判断”节点。○ 如果topic_type为service，则无论合规结果如何，都强制将review_result设置为pending_manual，并发送通知提醒运营人员复核。4.3 半自动发布流程升级1. 为知乎生成操作清单：○ 创建一个“代码执行”节点，用于生成zhihu_draft_{id}.md文件。○ 同时生成一个名为publish_checklist_{id}.txt的文本文件，其中包含推荐标题、发布时间建议和注意事项。2. 为小红书打包素材包：○ 创建一个“代码执行”节点，使用zip命令将生成的封面图、配图和文案打包成xiaohongshu_package_{id}.zip。○ 在操作清单中注明图片尺寸要求（1242x1660）和上传顺序。3. 封装“发布执行专家”为通用 Skill：○ 将上述为各平台生成草稿和清单的逻辑，抽象并封装为一个名为Publish_Draft_Generator的自定义 Skill。○ 未来新增平台时，只需为此 Skill 添加新的处理函数即可，无需重复开发。五、阶段三：多模态能力增强本阶段将引入图像与视频生成能力，使工作流能够生产更丰富的多模态内容。5.1 集成 Minimax 图像与视频生成能力1. 注册 Minimax Image Generation Skill：○ 在 XpertAI 的“技能中心”注册新技能。○ 技能名称：Minimax_Image_Generation。○ 配置参数：size(e.g.,1242x1660) 和style(e.g.,realistic,cartoon)。2. 注册 Minimax Video Generation Skill：○ 注册新技能Minimax_Video_Generation。○ 配置参数：duration(in seconds),resolution(e.g.,1080p),aspect_ratio(e.g.,9:16)。3. 在小红书专家中调用图像生成：○ 修改小红书策略专家的工作流。○ 在生成文案后，调用Minimax_Image_Generation技能，传入文案摘要作为提示词，生成封面图和配图。4. 在抖音/B站专家中生成分镜脚本：○ 为抖音/B站创建视频内容策略专家。○ 其核心任务是生成包含“钩子→痛点→解决方案→CTA”结构的分镜脚本。○ 调用Minimax_Video_Generation技能，将脚本转换为短视频，并生成 SRT 字幕文件。5.2 新增视频内容策略专家1. 设计视频脚本结构：○ 在视频内容策略专家的提示词中明确定义脚本结构：■ Hook (0-3秒)：提出悬念或痛点，抓住注意力。■ Problem (3-10秒)：深入阐述问题，引发共鸣。■ Solution (10-25秒)：介绍企业服务作为解决方案。■ CTA (25-30秒)：引导用户关注或咨询。2. 自动生成元数据：○ 除了脚本，该专家还需自动生成标题、简介、话题标签（如#黑科技#效率提升）。3. 输出结构化数据：○ 最终输出为一个 JSON 结构，包含title,script,cover_prompt,tags等字段，以及一个可读的.txt文本版本。5.3 素材复用机制1. 共享 AI 生成素材：○ 当同一选题需要在多个平台发布时，对于企业LOGO、标准色系等通用元素，只生成一次。○ 在工作流中设置一个全局变量shared_assets，存储这些通用素材的文件路径。2. 配置素材存储路径：○ 所有生成的图片和视频素材，必须按照以下规则存储：/data/xpertai-content/assets/{{current_date}}/{{platform}}/○ 例如，2026年5月1日在小红书平台生成的素材，路径为/data/xpertai-content/assets/2026-05-01/xiaohongshu/。六、阶段四：精细化运营本阶段致力于建立数据驱动的反馈闭环，实现工作流的自我优化与全自动化。6.1 效果数据回采1. 添加“延迟触发”节点：○ 在主工作流末尾，添加一个“延迟触发”节点，设置延迟时间为+24h。2. 调用各平台数据 API：○ 创建一个名为Effect_Data_Collector的 Workflow。○ 该工作流遍历publish_log.jsonl中过去24小时内的发布记录。○ 使用HTTP Request节点，分别调用微信公众号、知乎、小红书等平台的数据统计 API，获取阅读量、点赞数、评论数等指标。3. 写入 effect_data.jsonl 文件：○ 将采集到的效果数据，以追加写入的方式存入/data/xpertai-content/effect_data.jsonl文件。○ 每条记录包含content_id,read_count,like_count,comment_count等字段。6.2 自动调权与 A/B 测试1. 实现评分权重回归模型：○ 创建一个离线分析任务，定期读取effect_data.jsonl和topics_pool.json。○ 使用简单的线性回归模型，分析各评分因子（如热度、时效性）与最终效果（如阅读量）的相关性。○ 根据分析结果，动态调整scoring_weights.json文件中的权重值。2. 支持 A/B 测试：○ 对于高价值的选题，Supervisor可以生成多个版本（如不同标题、不同封面图）。○ 将这些版本提交给运营人员进行人工选择，或在未来接入自动化 A/B 测试平台。3. 建立运营看板：○ 利用外部 BI 工具（如 Metabase），连接/data/xpertai-content/目录下的 JSONL 文件。○ 创建看板，展示每日选题量、发布量、平均阅读量、互动率等关键趋势图。6.3 全流程自动化过渡1. 开放全自动发布：○ 对于topic_type为traffic且total_score高于阈值（如90分）的选题，移除人工审核环节。○ 在“合规检查”通过后，直接调用“发布与集成执行专家”通过 API 自动发布至微信公众号。2. 设置自动化阈值：○ 定义一个“自动化置信度”指标，综合考量compliance_pass_rate和historical_publish_success_rate。○ 当该指标大于95%时，允许service类型的内容也进入全自动发布流程。○ 此阈值可通过预留的自定义 Hook 接口，由外部系统进行动态调整。
