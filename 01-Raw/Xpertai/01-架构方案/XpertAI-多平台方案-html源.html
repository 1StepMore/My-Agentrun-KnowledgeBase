ELEGANT

多平台多模态内容自动化工作流设计方案

一、系统总体架构与模块协同

本方案基于 XpertAI 智能体编排平台，构建“Agent + Workflow 混合工作流”架构，实现多平台多模态内容的自动化生产与管理。系统通过分层设计，确保高自主性与高可控性的平衡，支持在单机本地环境中稳定运行。

五层系统架构

整体架构划分为五个逻辑层级，各司其职，协同运作：

层级 功能说明
触发与调度层 基于 XpertAI 的“定时任务工具集”配置每日早间触发器（Cron: 0 7 * * *），驱动选题生成与内容排期启动，是整个工作流的入口。
选题池与评分服务 构建 Topic Pool 数据结构，对候选选题进行加权评分、排序与末位淘汰，确保内容生产的质量与相关性。
多智能体与工作流编排层 系统核心处理引擎，融合 Agent 节点的创造性与 Workflow 节点的确定性，完成从选题到发布的全流程编排。
多模态能力层 以 Minimax 作为默认 LLM 提供文本生成能力，其 Skills 封装为图像生成、视频脚本生成等可调用工具，按需服务于内容创作节点。
外部集成层 对接微信公众号 API、文件存储系统及通知渠道，实现内容发布、素材上传与异常告警，完成闭环。

Agent 与 Workflow 节点选型原则

为兼顾灵活性与稳定性，不同场景采用不同类型的执行节点：

  • Agent 节点：用于需要强上下文理解与创造性输出的环节。
    • 典型应用：热点理解、选题生成、多平台内容草稿撰写。
    • 优势：能够利用 LLM 的推理能力，产出符合平台风格的多样化内容。
  • Workflow 节点：用于需要精确控制与规则刚性执行的环节。
    • 典型应用：选题评分计算、合规检查、API 调用、错误处理。
    • 优势：通过代码执行、条件路由和 HTTP 请求等节点，确保流程可靠、可追溯。

多智能体协作模式

本方案采用“Supervisor + 子智能体”的层级型架构，实现模块化分工与高效协同：

  • Supervisor Agent 作为主控角色，负责接收触发信号、分发任务给子智能体，并汇总各平台的生成结果。
  • 子智能体并行执行：多个“平台内容策略专家”并行工作，分别针对微信公众号、小红书、知乎、抖音/B站生成定制化内容，显著提升效率。
  • 聚合器节点：在 Workflow 中设置“变量聚合”节点，统一收集各子智能体的输出，交由后续的合规审查节点处理。

二、数据模型与状态持久化设计

为确保内容生产流程的可追溯性与状态一致性，本方案设计了结构化的数据模型，并明确了数据在工作流执行过程中的持久化与流转机制。所有核心业务实体均通过标准化字段定义，支持高效查询与审计。

核心数据实体定义

系统围绕三大核心实体构建：Topic（选题）、Content（内容制品） 与 PublishLog（发布日志）。三者通过唯一标识符形成关联链条，实现从创意到发布的全链路追踪。

Topic（选题）

作为内容生产的源头，每个选题记录其来源、类型、热度指标及评分结果，是驱动后续流程的关键数据单元。

字段名 类型 说明
id string 唯一标识符
title string 选题标题
description string 选题简述
type enum 类型：引流 / 服务介绍
created_at datetime 创建时间
hot_rank int 热榜排名
search_index float 搜索指数
duration_hours int 话题持续时长（小时）
service_tags list 关联服务标签（如“财税咨询”、“品牌策划”）
target_platforms list 目标发布平台列表
status enum 状态：待处理/处理中/已发布/已淘汰
score float 加权评分
score_time datetime 评分时间
eliminated_at datetime 淘汰时间（可为空）

Content（内容制品）

代表由特定选题生成的、面向具体平台的内容资产，包含多模态输出路径与审核状态。

字段名 类型 说明
id string 唯一标识符
topic_id string 关联选题 ID
platform string 发布平台（公众号/小红书等）
modality enum 模态类型：图文 / 视频
status enum 状态：草稿/审核中/待发布/已发布/失败
version int 版本号（支持迭代更新）
generated_at datetime 生成时间
updated_at datetime 最后修改时间
review_result string 审核结果（通过/驳回）
review_notes string 审核备注（如“需修改结尾引导语”）

PublishLog（发布日志）

记录每一次发布尝试的技术细节与结果，用于故障排查与成功率分析。

字段名 类型 说明
id string 唯一标识符
content_id string 内容制品 ID
platform string 发布平台
publish_time datetime 计划发布时间
result enum 结果：成功 / 失败
error_message string 错误详情（如 API 返回码）
retry_count int 重试次数

数据持久化与状态流转

  • 数据库存储：采用 SQLite 作为本地关系型数据库，持久化保存上述三张表，支持 ACID 特性，保障单机环境下的数据完整性。
  • 文件系统存储：生成的图文内容（Markdown/HTML）、图片文件（PNG/JPG）、视频脚本（JSON/SRT）等非结构化数据，按 /storage/data/output/{date}/{topic_id}/ 路径组织存储。
  • 工作流状态联动：
    • 工作流启动时，从数据库加载候选选题列表并存入会话变量 session.topics。
    • 评分完成后，更新 session.selected_topic 并同步写回数据库。
    • 内容生成节点读取 session.selected_topic，将输出文件路径写入 session.content_path，供发布节点调用。

四、多智能体协作与角色分工

为实现高效、专业化的内容生产，本方案在 XpertAI 项目空间内设计了一套模块化的“数字专家”体系。通过将复杂任务分解为多个专业角色，并采用层级化协作模式，确保各环节由最合适的智能体执行，从而兼顾创作质量与流程效率。

数字专家角色体系

系统共规划六类核心数字专家，每类专家均配置专属工具集，并在统一的项目协作空间内工作。以下是各专家的详细分工：

编号 专家名称 职责 所需工具 协作方式
1 热点监控与选题生成专家 监测社会热点，结合企业服务领域，生成引流型与服务介绍型两类候选选题 搜索、知识库检索、Minimax LLM 接收 Supervisor 指令，输出候选列表至评分节点
2 选题评分与排序专家 对候选选题执行加权算法，计算综合评分并进行排序 代码执行、数据库读写、变量聚合 接收列表，返回 Top N 排序结果
3 平台内容策略专家（分组） 定义并维护各平台（微信公众号、小红书、知乎、抖音/B站）的内容风格、结构规范与最佳实践 知识库（平台指南）、模板转换 由 Supervisor 分发任务，并行执行，独立产出
4 多模态内容生成专家 根据文本草稿调用 Minimax Skills，生成配图、封面及视频分镜脚本等多模态素材 Minimax Skills、图像理解、文档转换 接收文本指令，输出多媒体文件至指定路径
5 合规与风控审查专家 执行法律、版权、事实核查等刚性检查，确保内容安全合规 知识库（合规清单）、条件判断 统一审查所有平台的最终输出，决定是否放行
6 发布与集成执行专家 执行发布动作，包括调用 API 上传至微信公众号，或生成其他平台的操作清单 HTTP请求、代码执行、文件写入 汇总合规通过的内容，执行发布准备

层级化协作机制

本方案采用“Supervisor + 子智能体”的指挥架构，由一个主控 Agent 担任调度者角色，协调各子智能体的并行与串行操作。该模式既能发挥 Agent 的自主决策能力，又能通过 Workflow 节点保证关键流程的确定性。

Supervisor Agent 的标准工作流如下：

  1. 接收信号：监听来自“定时任务工具集”的每日触发信号。
  2. 启动选题：调用“热点监控与选题生成专家”，获取当日候选选题列表。
  3. 驱动评估：将候选列表传递给“选题评分与排序专家”，执行自动化评分。
  4. 分发创作：选取最高分选题，将其分发给各“平台内容策略专家”，启动并行内容生成。
  5. 汇集审查：收集所有平台的初稿，交由“多模态内容生成专家”补充素材，最终汇总至“合规与风控审查专家”进行终审。
  6. 执行发布：对于审查通过的内容，交由“发布与集成执行专家”完成后续动作。
  7. 记录日志：全程记录关键状态与事件，用于审计与复盘。

此设计实现了任务的高度模块化，便于未来对单个专家进行能力升级或替换，而无需重构整个工作流。

五、选题池管理与内容生成机制

本方案通过精细化的选题池管理与差异化的内容生成机制，确保内容生产兼具热点敏感性与业务关联度。以下从评分算法、淘汰策略及平台输出规范三个维度进行系统设计。

选题评分机制

为适配两类核心题材，设计独立的加权评分模型，确保选题决策既响应外部热度，又服务于企业转化目标。

引流题材评分模型

以社会关注度为核心，优先选择高流量、强时效性的热点话题，快速吸引潜在用户注意。

因子 权重示例 数据来源与计算方式
热度（热榜排名） 0.4 基于百度热搜、微博热搜等榜单排名进行倒序归一化处理，排名越靠前得分越高
时效性（发布时间差） 0.3 计算话题首次出现至当前时间的小时数，时间越短得分越高，超过24小时显著衰减
平台偏好 0.2 参考过去7天内该平台同类内容的平均点击率（CTR），反映历史表现趋势
历史点击率 0.1 匹配历史库中相似选题的最终CTR数据，作为效果预测因子

综合评分示例：某选题位于热榜第5名（得分0.9）、发布1.5小时内（得分0.96）、平台偏好高（得分0.8）、历史CTR为7.5%（得分0.75），其综合评分 ≈ 0.86。

服务介绍题材评分模型

以业务价值为导向，重点评估选题与企业服务能力的匹配程度，提升内容的转化潜力。

因子 权重示例 数据来源与计算方式
服务标签覆盖 0.4 统计选题中命中企业标准服务关键词（如“财税合规”“品牌定位”）的数量并归一化
案例适配度 0.3 判断是否存在已验证的成功案例可支撑该选题论述，有则加分，无则扣分
目标客群匹配 0.2 对照用户画像数据库，评估话题是否触及核心目标客户群体（如中小企业主）
转化潜力（历史） 0.1 提取过往同类内容的留资率（表单提交/咨询量）作为参考指标

综合评分示例：某选题覆盖4项核心服务标签（得分0.8）、有成功案例背书（得分1.0）、精准匹配目标客群（得分0.9）、历史留资率为5%（得分0.8），其综合评分 ≈ 0.87。

选题池生命周期管理

建立动态更新机制，保障选题池始终处于高质量、高相关性的状态。

  • 保留数量：选题池最大容量设定为 20条，超出后自动触发淘汰流程。
  • 淘汰周期：每日在新选题注入前执行一次清理，移除评分最低的条目。
  • 冷却机制：被淘汰的选题进入7天冷却期，期间禁止系统自动生成相同或高度相似主题，避免重复扰动。
  • 人工干预：运营人员可通过管理界面手动“复活”被误删的优质选题，系统将重新计算其分数并纳入候选队列。

多平台多模态输出规格

针对不同平台的内容消费习惯，定义标准化的输出结构与技术实现路径，确保内容形态与平台生态高度契合。

平台 输出结构 推荐规格 实现方式
微信公众号 封面图 + 正文（Markdown） + 配图（≤5张） + 摘要 正文1500-3000字，图文结合，逻辑完整 使用模板转换节点填充{{title}}、{{content}}变量，调用Minimax Skill批量生成配图
小红书 封面图 + 多图（3-9张） + 短文案 + 话题标签 文案≤500字，要点化排版，标签3-5个 采用清单式模板，Skill按场景生成系列风格统一图片，打包为ZIP供下载
