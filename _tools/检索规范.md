# 知识库检索规范（kb_search）

> **定位**：这是**所有 profile 共用的「外挂知识储备」入口**。任何 profile 在对话中遇到"该查知识库"的诉求时，都走这里。
> **实现**：`/mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py` ｜ **索引**：`_index/kb_index.json`（派生文件，不进 git）

---

## 1. 什么时候该检索（触发规则）

**去查**：
- 涉及**外部知识/方法论/行业事实**（"这行怎么做的""有没有成熟做法"）
- 需要**术语口径**（"什么叫按结果计费""FDE 是什么"）
- 需要**工具用法/官方结论**（Hermes / opencode / Palantir 等）
- 做**判断前找依据**（定价、合同、单位经济、竞品认定、落地方法）

**不必查**：用户私有信息（客户/报价/项目现状）、当前会话上下文、本机状态（用 terminal 查）。

**零命中的含义**：**先确认索引不是过期**，然后才代表"库里没有"——此时应该说"库里没有"，再决定联网或放弃，**不要凭记忆编**。

---

## 2. 怎么用（命令）

```bash
python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py "定价策略"            # 默认：Wiki + Draft
python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py "Palantir" --raw      # 含素材层（01-Raw）
python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py "outcome" --all       # 含参考存档层
python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py "本体" --json         # 机器可读（给程序用）
python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py "X" --limit 15        # 多给几条
python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py "X" --no-check        # 跳过新鲜度检查（最快）
```

**命中之后**：用 `read_file` 读文件本身（检索只给定位与摘要，不代替阅读）。

---

## 3. 检索机制（三层 + 兜底）

```
Pass1  关键词匹配：查询词 → 在 _keywords.yaml 里找别名 → 得到规范词（canonical）
Pass2  语义扩展：规范词 → 查 related（方向：具体→抽象，如 Palantir→语义层）→ 扩展词
Pass3  分层搜索：Wiki（+10）→ Draft（+5）→ Raw（0），同名文件去重保留最高层
兜底   关键词 0 命中 → 全文 AND 匹配（查询里每个 ≥3 字的词都出现才算命中）
```

**打分要点**（实测调优过，别随意改）：
| 信号 | 权重 | 说明 |
|:---|:---|:---|
| 标题含**整串查询** | +90 | 最强信号 |
| 正文/全文含整串查询 | +40 | |
| 标题命中（按词长加权 1–10） | ×8 | 长词更具体，权重更高 |
| 关键词精确命中 / 普通命中 | ×7 / ×4 | 受控词表命中 |
| 小标题命中 | ×2 | |
| 正文/全文命中 | ×1 | |
| 中文 bigram 命中（标题/关键词/小标题） | ≥2 且覆盖率 ≥60% 才计分 | 解决"中文复合词切不开"（如"合同验收"） |
| 规范词 / 相关词命中 | +18 / +10 | 词表驱动 |

**两条防噪规则**（都是实测踩出来的）：
1. **短词抑制**：查询里有 ≥4 字的词时，忽略 <3 字的词（否则查"AI 定价阶梯"会被 XpertAI 的 "AI" 顶到第一）
2. **bigram 覆盖率门槛**：只用 2 字命中不够（负样本"qqzzxx不存在的词条abcxyz"会误命中），要求覆盖率 ≥60%

## 3.5 输出成本（token 账，实测）

| 输出形态 | token | 何时用 |
|:---|:---|:---|
| 默认（含关键词/证据/命中理由/160 字摘要） | **~2173** | 不确定读哪个 → 靠摘要判断 |
| `--brief`（只给 层级/标题/路径） | **~541**（省 75%） | 已知道要找什么，只要定位 |
| `--json` | ~1184 | 程序化消费 |

**常驻开销（每次请求都付）**：SOUL 里的检索段 **334 tok**（default SOUL 的 14%）+ 技能描述行 82 tok；
技能正文（1597 tok）与检索前置块**只在被加载时消耗**。记忆里**不写**（预算溢出）。

**对比老办法**（同一件事：全库找"定价"）：grep 全库 **31.5s / 4081 tok**，且通常要 2–4 轮才能定位；
kb_search **0.44s / 2173 tok**，一次给出排序+摘要 → 通常 1 轮。**真正吃 token 的是轮次**（每轮重发整个上下文），
所以"一轮定位"比"省输出"更重要。

## 4. 效率与鲁棒性（为什么这么设计）

| 特性 | 做法 | 实测 |
|:---|:---|:---|
| **查询快** | 索引内**预归一化**字段（建索引时算好），查询不再做正则 | **0.34s / 次**（含 python 启动） |
| **新鲜度检查 O(1)** | **脏标记 + 30 分钟时间窗**；不做全库遍历 | 全库遍历在 `/mnt/d`(DrvFs) 上要 4–5s，已废弃 |
| **写入自动失效** | `kb_finalize.py`（写入收尾必跑脚本）会打脏标记 → 下次查询自动重建 | 已挂，实测有效 |
| **重建快** | 多线程读取（8 workers），Raw 正文只留 600 字摘要 | **4.3s / 1320 条**（原 14s） |
| **严格可验** | `--check` 做全遍历新鲜度检查；`--selftest` 正/负样本 + 新鲜度断言 | 自检 **8/8 通过，退出码 0** |
| **排噪** | 默认排除 `.git`/`_backup`/`_index`/`参考存档`；存档层要 `--all` | 索引 1320 条（存档 2200+ 页不入索引） |
| **不崩** | 纯 Python 遍历（中文路径/NUL 安全）；frontmatter 解析失败退化为正则，**不清空** | 建索引错误 0 |

**已知边界（诚实标注）**：
- 索引默认**不含参考存档层**（Palantir/Anthropic 全量 2200+ 页）→ 查存档内容需 `--all`
- 30 分钟时间窗意味着**外部直接改文件**（不经 kb_finalize）最多滞后 30 分钟；`--check` 可当场验证
- 目前是**词面匹配 + 词表扩展**，没有语义向量检索；同义但用词完全不同的查询可能漏（此时靠 bigram 与词表 aliases 兜）

## 4.5 质量门禁与方案选型评估

```bash
python3 _tools/kb_eval.py                 # 质量评估集（21 用例 + 4 负样本）
python3 _tools/kb_search.py --selftest    # 机制自检
```

**实测基线（2026-09-24，21 用例 + 4 负样本）**：

| 组 | 考什么 | 基线（纯词面） | 现在（词面+语义映射） |
|:---|:---|:---|:---|
| A 词面/专名 | 术语、工具名 | 8/8 | **8/8 = 100%** |
| C 关键词式 | 多词无连接词 | 4/6 | **5/6 = 83%** |
| B 自然语句/同义改写 | 语义召回能力 | **0/7 = 0%** | **4/7 = 57%** |
| D 负样本 | 库里没有的主题必须 0 命中 | 4/4 | **4/4 ✅** |
| E code 场景 | 技术/英文/工具名 | 9/10 | **7/7 = 100%** |
| F content 路由 | 品牌/平台/项目（**库外**） | ⚠️ 返回垃圾 | **5/5 = 100%** |
| 合计 | | 12/21 (57%) | **27/33 (82%)** |

### 分 profile 实测（决定"是否适合所有 profile"）

| profile | 典型问法 | 纯词面 r@5 | 结论 |
|:---|:---|:---|:---|
| **code** | 技术/英文/关键词（harness、MCP、评测） | **9/10 = 90%** | 词面已足够，嵌入收益小 |
| **default** | 业务语言、自然语句（定价/合同/单位经济） | 0/7 → 4/7 | **受益最大** |
| **content** | 品牌/平台/内容运营 | **1/10 = 10%** | ⚠️ **不是检索问题，是内容边界问题**：品牌资产/平台规则**按设计不在 KB**（在 `00-Records/brand-assets`）→ 已加**路由提示**（未命中时指明该去哪层），否则返回"最近的垃圾"比返回空更糟 |

### 方案选型：为什么**不**上嵌入模型（决策记录）

| 候选 | 成本 | 实测收益 | 判定 |
|:---|:---|:---|:---|
| **手写语义映射**（`_tools/synonyms.yaml`，29 条） | **0 依赖 / 0 延迟 / 可评审可迭代** | B 0/7→4/7，ALL 57%→81% | ✅ **已采用** |
| jieba 分词 + BM25 | 轻依赖（~20MB） | 未测（C 组已 83%，边际小） | ⏸ 备选 |
| fastembed/bge-small-zh + ONNX | 模型 ~100MB + onnxruntime ~200MB；**每进程加载 0.3–1.5s**（CLI 按次调用，会把 0.39s 查询拖到 1–2s）；4 核/7GB 上跑 | 预期补 B 组剩余 3/7 | ❌ **现阶段不做** |
| 向量数据库（FAISS/Milvus） | 服务运维 | 1320 条向量 numpy 点积 <1ms | ❌ 无必要 |
| API 嵌入 | 按量计费 + 离线不可用 | 同嵌入 | ❌ 与"离线自持"原则冲突 |

**嵌入的触发条件（写死，避免情绪化决策）**：
1. 语义映射迭代到 **60+ 条**后，B 组仍 **< 60%**；且
2. 评估集里**自然语句类查询占比 > 20%**（即真实使用中确实大量是整句问法）；且
3. 先解决"每进程加载模型"的延迟问题（常驻服务或查询侧只嵌查询+文档向量预存）。

**本轮修复的两个真 bug**（都靠门禁抓出）：
1. 「客户 续费」两个 2 字词被"短词抑制"误杀 → 0 命中（改为只抑 ASCII 噪声如 "ai"）
2. 兜底 bigram 过松 → 乱码也命中（收紧 + 负样本守卫）

### 短别名 `kb`（省 prompt token）

`~/.local/bin/kb` → `python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py "$@"`（在 PATH 上，非登录 shell 也可用）。
三个 profile 的 SOUL 里只写 `kb "关键词"`（KB 段 **334 → 163 tok，降 51%**）。
**若 PATH 里找不到 `kb`**：用完整路径 `python3 /mnt/d/Hermes-KnowledgeBase/_tools/kb_search.py`，并重建别名。

## 5. 维护

```bash
python3 _tools/kb_search.py --stats        # 索引统计（条数/构建时间/体积/脏标记）
python3 _tools/kb_search.py --rebuild      # 手动重建
python3 _tools/kb_search.py --selftest     # 自检（改完必跑；退出码 0 才算可用）
python3 _tools/kb_search.py --mark-dirty   # 外部改动后手动打脏标记
python3 _tools/kb_eval.py                  # 质量评估（改检索后必跑，r@5 不许下降）
```

**改这个脚本的铁律**：
1. 改完**必跑 `--selftest`**——它含正/负样本与新鲜度断言（这是"机制必须能自证在工作"）；
2. **别去掉短词抑制与 bigram 覆盖率门槛**——那是修过两个真 bug 的补丁；
3. 索引是派生文件（`.gitignore`），**不要提交**；
4. 新增维度/大量素材后，若查询变慢，先看 `--stats` 的体积与脏标记，再考虑调 `BODY_CAP`。

## 6. 各 profile 的接入方式

- **SOUL.md**（三个 profile 均已挂）：说明"先检索再回答"+ 命令，**每次会话必然注入**
- **记忆**：**不写**（记忆有字符预算，且 SOUL 已足够；实测 default 记忆已 2179/2200，加进去会溢出）
- **技能**：`knowledge-base/kb-retrieval`（三个 profile 各一份）—— 技能名+描述**每轮注入**，是第二个触发面
- 触发点：任何"该查知识库"的诉求 → 直接跑上面的命令，不必先问用户
- **检索前置（针对高频 skill）**：在容易凭经验下判断的 skill 顶部加一段「⭐ 检索前置」（开工前必查），已装：
  `ai-landing`、`service-pricing-review`、`localization-pricing-review`、`ai-landing-prerequisite-prep`。
  新增同类 skill（判断类/报价类/落地类）时照此加一段 —— 格式见本文件 §1 的触发规则。
